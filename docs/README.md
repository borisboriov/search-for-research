# Карта документов Search For Research

Общая вводная и единственный обзор текущего состояния — [бриф](product/brief.md).
Эта карта помогает найти первичные материалы и отличить действующий документ
от исторического результата. Правила работы — [AGENTS.md](../AGENTS.md).

## Где работаем

| Место | Что хранится | Как используется |
|---|---|---|
| Репозиторий `~/Projects/search-for-research` | Код, текстовые документы продукта, требования, отчёты и доказательства | Рабочие оригиналы текстов; GitHub `borisboriov/search-for-research` приватный |
| Папка `~/Desktop/Search for Research` | Паспорт, питч, обоснование рынка и другие бинарники в `01_core/`; исходные исследования, персональные данные, архив | Локальные рабочие оригиналы; правила её AGENTS |
| [Google Drive](https://drive.google.com/drive/folders/19pFtXT0ZwgX30UjKgWZRLKFKIWp9vogz) | Опубликованные копии для преподавателей и проверяющих | Витрину обновляет Борис после локальных правок, с сохранением ссылок; автосинхронизации нет |

Локальные чаты продуктового проекта открываются из папки документов,
технический CLI Борис запускает сам в терминале PyCharm из репозитория.
Управление компьютером и автоматический запуск сессии в этот процесс не входят.
Оба входных AGENTS направляют к одному
брифу; отдельного праймера и копий контекста в настройках чатов не ведём.
Исторический документ выбора VPS в старом проекте Claude не заменяет
`deploy/README.md` и проверку фактических параметров эксплуатации.

## Как войти в работу

1. [Бриф](product/brief.md): «Где мы сейчас», контекст, команда и рабочий цикл.
2. Поставленная задача, связанные issues/PR и последние решения Бориса;
   [доска](https://github.com/users/borisboriov/projects/5) показывает задачи и статусы.
3. [DECISIONS.md](DECISIONS.md): сводка действующих решений и записи по теме.
4. Отчёт нужной итерации: §0 «Резюме для человека», DoD, ограничения и ревью;
   затем доказательства, на которые он ссылается.
5. Специальные требования и процедуры — по поручению, без чтения всей истории.

| Вопрос | Канонический источник |
|---|---|
| Принятые продуктовые цифры и формулировки для курса | Паспорт `01_core/Паспорт_Search_For_Research.xlsx`; питч и обоснование согласуются с ним |
| Текущее состояние и следующий шаг | `product/brief.md`, «Где мы сейчас»; свежие факты имеют ссылки на issues и доказательства |
| Что требуется реализовать | Спека активной итерации и связанные issues; целевой MVP — `product/mvp_spec.md` |
| Что измерено и на каких условиях | Отчёт, исходные метрики и судейская разметка соответствующего прогона |
| Почему выбрано решение | `DECISIONS.md`; исторические записи не являются новым заданием |
| Что разрешено агенту и какие проверки нужны | AGENTS рабочей папки и процедура конкретной задачи |

`make docs-check` проверяет живые ссылки и состояние брифа против
`meta.json` боевого индекса и `ApiSettings`; `make docs-check-live` — также
против боевого `/api/health`. Бриф обновляется продуктовым потоком после
значимого результата или решения. В журнале решений его состояние не копируется.

## Раскладка

```
docs/
  README.md            навигация и ограничения источников
  DECISIONS.md         действующие решения и датированные основания
  SESSIONS.md          замороженная история сессий 1–23
  PILOT_TEST_GUIDE.md  сценарий пилота
  reports/             отчёты итераций
  metrics/             генерируемые JSON метрик
  specs/               закрытые спеки, история требований
  product/             единый бриф и специальные продуктовые материалы
```

[Оглавление продуктовых материалов](product/README.md) ведёт к плану курса,
спеке MVP, исследованиям, расчётам и подготовке защиты. Спека открытой итерации
лежит в корне репозитория, закрытой — в `specs/`.

Передача работы и продуктовый вердикт сохраняются в issue/PR; отдельный файл
передачи и отчёт продуктовой проверки не нужны. Правки паспорта — раздел отчёта
по ячейкам и issue `human` `docs`. `SESSIONS.md` заморожен 27.09.2026;
`product/brief_history_qa.md` хранит историю и материалы к защите, новые раунды
в него не дописываются. Отчёты, метрики, разметка и снимки доказательств
сохраняются; аудит старых файлов сам по себе не разрешает их удалять.

Независимый ревьюер возвращает результат координатору; тот сохраняет итог
в PR с проверенными base/head и ссылками на оставшиеся находки. Отдельный
REVIEW-файл по умолчанию не создаётся. Для техитерации краткий итог также
включается в существующий отчёт; обычная правка документов нового отчёта не требует.

## Откуда нельзя брать цифры

- **Цифры качества для паспорта и защиты** — только слепой судья:
  `reports/SFR5c_REPORT.md` §13.5 и §13.11, `metrics/sfr5c_deploy_metrics.json`;
  действующие значения с условиями — раздел «Где мы сейчас» `product/brief.md`.
  Колонки «накопленная разметка» и все абсолютные Success@k отчётов до 26.09
  получены судьёй, который сам собирал каталог, — они для сравнения отчётов между
  собой, не для внешних документов (`DECISIONS.md` 26.09, канонический судья).
- **§4 и §6 `SFR5c_REPORT.md`** — измерение каталога **9 010**, а выложен 9 002
  (§13). Действующие числа — §13.
- **Пороги** принадлежат паре модель×индекс: действующие — в `ApiSettings`
  (`apps/api/src/sfr_api/settings.py`), `/health` и §13.4 `SFR5c_REPORT.md`; числа из
  отчётов SFR-2, SFR-5, SFR-5b — пороги своих индексов.
- **nDCG между отчётами несравним** (судейский пул разный); Success@k — только на
  неизменных наборах 22 и 24.
- **Калибровочные таблицы SFR-5, SFR-5b и OOD-блок §4 SFR-5c** считались на 19
  посторонних; действующий набор — 17 (`DECISIONS.md` 26.09). Воспроизводить их —
  с архивным набором (`make metrics-sfr5c`, `make ood19-sfr5c`).
- **Генерируемые отчёты** (`REPORT.md`, `SFR1_REPORT.md`, `SFR2_REPORT.md`)
  переписываются своими командами — править их руками бессмысленно.
- **Review-выборки в `data/eval/review/`** — рабочие выходы целей и CLI, каждый
  прогон их переписывает; доказательство — только файлы
  `packages/sfr-match/eval/` из таблицы «Доказательства» его README (#143).
- **Цифры-деньги** (рынок, стоимость хостинга) — не менять без решения Бориса
  (`product/market_stretch_map_2026-08-08.md`); `03_archive/` папки документов —
  не источник цифр.
