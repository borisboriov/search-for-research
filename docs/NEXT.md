# NEXT — план SFR-3 (фронтенд)

Вход: работающий API (`apps/api`, SFR-2) на корпусе 535 профилей МФТИ+МГУ,
модель FRIDA, порог отсечки 0.27. Итоги — `docs/SFR2_REPORT.md`.

**Дизайн придёт от Бориса отдельно.** Он ведёт дизайн-ресерч параллельно;
интерфейсных решений здесь не предвосхищаем — ниже только то, что следует из
измерений и из контракта API. Всё, что касается вида экранов, порядка блоков и
формулировок для пользователя, ждёт его материалов.

## Что уже решено (не переоткрывать)

- **Модель — `ai-forever/FRIDA`**, запасная — `paraphrase-multilingual-mpnet-base-v2`.
  Переключение: `SFR_API_MODEL` плюс собранный под неё индекс и свой порог (0.43).
- **Карточки НР открытые и бесплатные**, без авторизации (план MVP v1.3).
  Монетизация — на сервисах вокруг данных, не на данных.
- **Порог 0.27 — предупреждение, а не отказ.** Выдача возвращается всегда;
  `below_threshold: true` означает «уверенных совпадений нет, вот ближайшее».
- **В индекс кладём полный `profile_text`.** Проверено экспериментом: только темы
  дают 82% Success@5 против 100%, а «темы + названия» не экономят текст.
- **Бэкенд поиска выбирается автоматически**: FAISS на Linux, NumPy на macOS.
- **Индекс собирается офлайн** (`make index-sfr2`) и монтируется в контейнер.
- **PostgreSQL/pgvector, RAG-объяснения, дедупликация авторов, новые вузы** —
  по-прежнему вне скоупа.

## 1. Next.js-фронт (`apps/web/`)

- Одна страница поиска: поле ввода (3–500 символов), выдача 5–10 карточек,
  состояние «уверенных совпадений нет» при `below_threshold`.
- Открытая страница НР по `GET /api/supervisors/{author_id}` — под неё эндпоинт
  и делался.
- **Что показывать на карточке в первую очередь — названия работ, а не аннотации.**
  Это не вкусовое: эксперимент SFR-2 показал, что названия несут больше сигнала,
  чем фрагменты аннотаций. Пользователь должен видеть то же, на что смотрит модель.
- Ждать от API секунду и не выглядеть сломанным: p50 ≈ 0.6 с, при нескольких
  одновременных запросах — до 2 с. Скелетон/индикатор обязателен.

## 2. Что нужно на стороне API до публичного запуска

- **Rate limiting.** Карточки открыты и без авторизации — значит, без защиты от
  перебора всего корпуса. Для демо приемлемо, для публичной ссылки нет.
- **Метрики и логи запросов.** Сейчас непонятно даже, сколько запросов пришло.
  Логировать текст запроса, top-1 score и `below_threshold` — это и мониторинг,
  и материал для следующей калибровки порога.
- **Кэш ответов на повторяющиеся запросы.** При 2 запросах в секунду у FRIDA это
  дешёвый способ поднять потолок.

## 3. Данные и оценка (долги)

- **Внешний тест-сет.** Файл и инструкция готовы (`eval/external_queries.jsonl`,
  `eval/README.md`), запросы собирают Борис и Света. Это единственный способ
  узнать, насколько завышены нынешние Success@1/@5: golden set написан агентом,
  читавшим темы корпуса.
- **Проверка судейства SFR-2** — 20 пар в `eval/judgments_for_review_sfr2.md`.
- **Дедупликация авторов** (долг SFR-0): расщеплённые профили видны в выдаче.
- **Рост корпуса.** 535 профилей — всё ещё пилот. Вопрос «что будет на 5–50 тысячах»
  открыт; там же впервые станет осмысленным приближённый поиск вместо IndexFlatIP.

## 4. Вне SFR-3

- PostgreSQL + pgvector — когда корпус перерастёт десятки тысяч профилей.
- RAG-объяснение «почему этот НР».
- Личные кабинеты, сохранённые подборки, переписка с НР — всё, что требует
  авторизации.
