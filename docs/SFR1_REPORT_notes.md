## Рекомендация

**В SFR-2 берём `ai-forever/FRIDA`** (`search_query:` / `search_document:`, dim 1536, 823M параметров).

| Почему | Цифра |
|---|---|
| Единственный вариант со 100% Success@5 на in-domain | 22/22 запросов |
| Единственный, кто взял все edge-запросы (короткие, с опечатками, периферийные) | 4/4 |
| Работает на всех кросс-языковых запросах (ru-запрос → en-профиль) | q11–q14 — все с grade=2 в топ-1 или топ-3 |
| Шкала score пригодна для порога отсечки (в отличие от E5) | средний зазор top1–top10 = 0.069 против 0.016 у E5 |

**Запасной вариант — `paraphrase-multilingual-mpnet-base-v2`**: 21/22 in-domain, лучший
nDCG@10 (0.732) и MRR (0.932), при этом **в 6.8 раз быстрее** (20 мс против 136 мс) и
**в 3 раза меньше** (278M против 823M). Если латентность API станет проблемой — это
готовая замена ценой одного запроса из 22.

Отдельно стоит отметить, зачем брать более тяжёлую FRIDA: mpnet обрезает вход на
**128 токенах** (это его штатный `max_seq_length`), то есть видит только имя, строку
тем и начало первой работы — и всё равно берёт 21/22. Значит, основной сигнал сидит
в строке ключевых тем, а не в аннотациях. FRIDA (512 токенов) выигрывает ровно на
тех запросах, где нужны детали из аннотаций (q02 — медицинские изображения).
Это гипотеза для SFR-2 про состав `profile_text`, а не только про модель.

## Дал ли эффект clean

**Практически нет.** Чистка (LaTeX + «аннотации-списки авторов») меняет 46 из 261
профилей и убирает 2998 символов — медиана 30 символов на профиль, то есть ~2% текста.

| Модель | Топ-5 изменился | Топ-1 изменился | Success@5 |
|---|---|---|---|
| frida | 4/30 | 1/30 | 100% → 95% (**хуже**) |
| e5-base | 17/30 | 2/30 | 91% → 95% (**лучше**) |
| mpnet | 4/30 | 0/30 | без изменений |
| minilm | 9/30 | 0/30 | без изменений |
| bm25 | 1/30 | 0/30 | без изменений |

Разнонаправленные сдвиги на ±1 запрос при 22 запросах — это шум, а не эффект.
Вывод: **проблемы №1–2 из SFR-0 (LaTeX-мусор, аннотации-списки авторов) на качество
поиска почти не влияют** — их масштаб (2% текста, 46 профилей) слишком мал.
Чистку в SFR-2 оставляем включённой: она бесплатна, делает выдачу читаемее для
человека и понадобится, когда профили начнут показывать на сайте.

## Что показал BM25 (нужен ли гибрид)

**В текущем виде — нет.** BM25 даёт 41% Success@5 против 100% у FRIDA, и причина
не в качестве ранжирования, а в языке: **у 16 из 30 запросов top-1 score равен нулю** —
русский запрос не пересекается по словам с англоязычным профилем вообще. Пример q17
(«Нейтринные эксперименты и безнейтринный двойной бета-распад»): BM25 случайно
поставил на первое место правильного Инжечика, но со score 0.000 — это не находка,
а порядок исходного списка.

Там, где лексика совпадает (русскоязычные названия работ, латинские термины вроде
«BM25»-совместимых «NLP», «deep learning»), BM25 работает — отсюда 9/22.

Гибрид имеет смысл только вместе с переводом запроса или двуязычным индексом;
как отдельная задача это выходит за SFR-2. **Что BM25 действительно даёт сейчас —
это нижняя граница**: 41% — вклад чистого совпадения слов, всё сверх этого
(до 100%) — вклад семантики. Ради этой цифры эксперимент и ставился.

## Порог score для «мы никого не нашли»

Честный ответ: **надёжного порога по этому golden set вывести нельзя**, и вот почему.

Из 4 out-of-domain запросов **два оказались не out-of-domain**:

- **q27 «история России XIX века»** — в корпусе есть М. С. Горбачёв с темами
  «Soviet and Russian History» и книгами о перестройке. Не XIX век и не научная
  историография, но и не «ничего похожего» (оценка 1).
- **q29 «кулинария и технология выпечки хлеба»** — в корпусе есть В. В. Иванов
  с темой «Food Industry and Aquatic Biology» и работой про экструдированные
  зерновые хлебцы (оценка 2!) и Е. Котенкова с пищевой химией (оценка 1).

То есть у 261 профиля МФТИ хвост шире, чем кажется, и два «заведомо посторонних»
запроса получили осмысленные ответы. Это хорошая новость для продукта и плохая —
для калибровки порога: истинно посторонних запросов остаётся **два** (q28 право,
q30 маркетинг), и по двум точкам порог не ставят.

Что видно по этим двум точкам для FRIDA:

| Порог top-1 | Ошибочно отсечёт in-domain | Верно отсечёт истинно-OOD |
|---|---|---|
| 0.30 | 0 / 22 | 1 / 2 |
| 0.34 | 0 / 22 | 1 / 2 |
| **0.35** | 2 / 22 | 2 / 2 |
| 0.40 | 5 / 22 | 2 / 2 |

**Рабочее решение для SFR-2:** порог `0.35`, но не как отказ, а как **предупреждение** —
«уверенных совпадений не нашли, вот ближайшее». Жёсткий отказ при таком перекрытии
(минимум in-domain 0.342 против максимума истинно-OOD 0.344) отрежет живые запросы.
Порог перекалибровать на расширенном golden set (нужно ≥15 честных OOD-запросов).

**E5 для порога непригоден в принципе**: все его score лежат в диапазоне 0.78–0.86,
средний зазор между 1-м и 10-м местом — 0.016. Отличить «нашли» от «не нашли»
по такому числу нельзя. Это отдельный аргумент против E5, помимо метрик.

## Пять разобранных примеров

### 1. Удача: q17 «Нейтринные эксперименты и безнейтринный двойной бета-распад» (FRIDA)

```
1. Л. В. Инжечик      0.436  grade=2   ← GERDA, 0νββ в Ge-76: точное попадание
2. N. Nikitin         0.404  grade=1
3. P. Egorov          0.386  grade=1
```
Узкий русский запрос по англоязычному профилю. В корпусе ровно один человек
занимается 0νββ — и он на первом месте. BM25 на этом же запросе даёт score 0.000
на всех позициях: ни одного общего слова.

### 2. Удача: q11 «оптимизация маршрутов доставки и алгоритмы для логистики» (FRIDA)

```
1. Anton Agafonov     0.442  grade=2   ← Transportation Planning and Optimization
2. Boris Goldengorin  0.433  grade=2   ← Vehicle Routing Optimization Methods
3. L. A. Beklaryan    0.414  grade=2   ← генетические алгоритмы для транспортных сетей
```
Три из трёх релевантных НР корпуса — в топ-3, и все три профиля англоязычные.
Это и есть кросс-языковой мэтчинг, ради которого затевалась проверка.
Для сравнения, `minilm` на том же запросе: топ-1 — М. С. Горбачёв (grade=0).

### 3. Промах: q02 «нейросети для медицинских изображений» (mpnet и e5-base)

```
[mpnet]    1. Victor Kazantsev       0.579  grade=1   (нейроинтерфейсы, ЭЭГ)
[e5-base]  1. M. V. Kovalchuk        0.834  grade=1   (рентгеновская визуализация)
[frida]    1. V. A. Knyaz            0.456  grade=2   ← верно
```
**Виноват не запрос и не профиль, а модель.** Правильный ответ — В. А. Князь
(ThermalGAN, YOLO, pix2pix + тема «Dental Radiography and Imaging») — требует
прочитать названия работ. mpnet до них не доходит (обрыв на 128 токенах), e5-base
цепляется за слово «медицинский» в темах и уводит в биологию. FRIDA справляется.

### 4. Промах: q10 «data science в физике: анализ больших данных, Python, ML-пайплайны» (frida_clean)

```
[frida]        топ-5: ... 5. Yu. V. Stenkin  0.387  grade=2   ← прошёл впритык
[frida_clean]  топ-5: ... 5. A. Zelenski     0.388  grade=1   ← Стенкин выпал на 6-е
```
Единственный запрос, который FRIDA теряет — и только в clean-варианте, где
удаление 30 символов LaTeX сдвинуло пятую позицию. **Виноват запрос**: он смешивает
метод (Python, ML) с предметом (физика), а в корпусе таких людей единицы —
T. Aushev с темой «Computational Physics and Python Applications» и Жемчугов
с ATLAS Computing Grid. Разница между 5-м и 6-м местом — 0.001. Это не деградация
модели, а неустойчивость на границе топ-5.

### 5. Out-of-domain: q29 «кулинария и технология выпечки хлеба» (FRIDA)

```
1. В. В. Иванов       0.363  grade=2   ← «Food Industry and Aquatic Biology»,
                                          работа про экструдированные зерновые хлебцы
4. Elena Kotenkova    0.340  grade=1   ← качество мясных продуктов, съедобные плёнки
```
Запрос задумывался как заведомо посторонний, а модель нашла реальный ответ.
Причина — состав корпуса: 261 профиль МФТИ включает пищевую промышленность.
Вывод двойной: (а) модель ведёт себя правильно и не выдумывает; (б) **автор
golden set (то есть я) плохо знал корпус** — это ограничение методики, а не модели.

## Вердикт по порогу проекта

**Достигнуто с запасом.** Порог — Success@5 ≥ 70% на in-domain; FRIDA даёт **100%**
(22/22), mpnet — 95%, e5-base — 91%. Даже слабейшая из «настоящих» мультиязычных
моделей проходит порог. Порог оказался не слишком требовательным для этого корпуса —
на 261 профиле одного вуза задача проще, чем будет на кросс-вузовом индексе.

Отдельно: **англоязычная `all-MiniLM-L6-v2` из раннего паспорта проекта даёт 27%** —
она проваливает 16 из 22 русскоязычных запросов и на q11 ставит первым Горбачёва.
Это измеренное обоснование смены модели в документах проекта: разрыв с FRIDA —
**73 процентных пункта**.

## Ограничения эксперимента (честно)

1. **261 профиль одного вуза**, отобранный по works_count desc — верхушка МФТИ.
   На кросс-вузовом корпусе в 10–100 раз больше конкуренция за топ-5 вырастет,
   и 100% почти наверняка просядут.
2. **Судья — LLM (я же)**, один, без второго мнения и без замера согласованности.
   Оценки в `eval/judgments.jsonl` с обоснованиями и 20 случайных пар в
   `eval/judgments_for_review.md` — именно для того, чтобы человек их перепроверил.
   До проверки все цифры в этом отчёте следует читать как предварительные.
3. **Golden set составлен автором после чтения топ-15 тем REPORT.md** — распределение
   запросов подогнано под корпус. Реальные студенты будут спрашивать иначе,
   и доля «ничего не нашли» будет выше.
4. **Два из четырёх OOD-запросов оказались не OOD** — порог отсечки по факту
   калибруется по двум точкам. Это самая слабая часть эксперимента.
5. **Пул — топ-5 всех вариантов**; позиции 6–10 в nDCG@10 почти не оценены и
   считаются нерелевантными. nDCG в таблице систематически занижен для всех
   моделей одинаково, поэтому для сравнения годится, а как абсолютная величина — нет.
6. **Один прогон, без доверительных интервалов.** Разница между FRIDA (100%) и
   mpnet (95%) — это один запрос из 22. Утверждать по такой выборке, что FRIDA
   строго лучше, нельзя; можно лишь сказать, что она не хуже и устойчивее на edge.
7. **Латентность мерилась на macOS/M-серии, CPU, batch=1**, после прогрева модели.
   В контейнере на сервере цифры будут другими.
