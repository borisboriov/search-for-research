# Измерение компактного GPT verifier, compact-v1

Метод фиксируется до новых baseline/compact вызовов. Это личный эксперимент
в PR194; не свидетельство допустимости массового продукта или человеческая разметка.
Цель — сократить input/output GPT при сохранении семантических проверок.
Новые сравнительные jobs начинаются только после12 пригодных результатов
свежего основного конвейера, без преждевременного перехода к оптимизации.

## Материалы и последовательность

Три использованных сложных контрольных профиля из сохранённого cache-verifier-v1:
A5015573260, A5027597767, A5100670875, по четырём исходным атомам. Входы берутся
из `enrichment-verifier-three-20261009/inputs`; если конкретного файла нет — из
неизменённого `enrichment-verifier-pair-20261009/inputs`, затем
`enrichment-verifier-benchmark-20261009/inputs`. При конфликте SHA остановка,
без выбора удобного варианта. Старые ответы/судейства не передаются проверяющим.
Это development set, не независимый тест.

Каждый source JSON закрепляется SHA. Оба варианта получают побайтно одинаковые
семантические данные: профиль, атомы, quotes/dates/URLs/objects и профильные refs.
Ни одна цитата/предметный якорь не удаляется, не пересказывается и не переводится.
Baseline: полная semantic-v3 инструкция и дублированная схема в user JSON,
как текущий native verifier. Compact: короткая эквивалентная инструкция из
`enrichment_verifier_compact_v1.md`; schema передаётся только через штатный
`--output-schema`, без дублирования в user JSON. Оба: gpt-6.1-sol/high,
новый `codex exec --ephemeral`, изоляция без tools/web, timeout600с с общим
дедлайном04:49:55. Единственная попытка каждого stage, без автоповторов.

Порядок заранее: G baseline→compact; K compact→baseline; B baseline→compact.
Время/кэш зависят от последовательности; причинной рандомизации времени нет.
Считать input, cached subset input, output including reasoning, reasoning subset,
input+output, wall time, completion/semantic validity, tool calls0. Деньги и
квоты только реально раскрытые; токены не преобразовывать в платежи подписки.

## Независимая проверка и критерий выбора

Два слепых gpt-6-astra/xhigh jobs: первый G; второй K+B. Один независимый
контекст на пакет, без истории разработчика/предыдущих судей/ожидаемого победителя.
Дословные items/profile_assessments/summary; provenance/model/usage/paths/derived
скрыты. SystemRandom перестановка A/B по профилю сохраняется отдельно. Судья
получает полную semantic-v3, общий источник и два ответа. Grade/error/severity
фиксируются по прежней judge-schema. Судейская оценка не человеческий эталон.

Выбирать compact для нового контроля только при 3/3 пригодных ответах обоих,
без новых critical/high относительно baseline и без снижения correct атомов и
профильных осей по тому же судье; суммарный input минимум на15% ниже,
input+output минимум на10% ниже. При провале — сохранить обе версии и причину,
не объявлять экономию доказанной, не заменять текущий метод.

После успешного выбора — два дополнительных свежих профиля (новые ID по
замороженному seed19319420261015, исключить все предыдущие sample.json),
по одному GLM collector и выбранному независимому Sol verifier. Та же публичная
политика, исходные4search/8resources600s/concurrency1, фиксированные ID до вызовов.
Один слепой Astra/xhigh job на оба новых контроля с материалами и одним ответом
(вторая позиция не выдумывается; отдельная одноответная schema). Осталось до4
judge jobs ночи, весь итог до30 новых профилей/100 содержательных jobs.
После04:30 новые профили/партии запрещены. При quota/access STOP, remainingCodex
<=15% или исчерпании времени новые GPT jobs не начинать; incomplete сохранить.
