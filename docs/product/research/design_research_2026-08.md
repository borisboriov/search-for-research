## 1. Как сегодня выбирают дизайн сайта (общая практика)

Современный процесс — это не «нанять дизайнера и довериться вкусу», а последовательность из четырёх слоёв, каждый из которых решается своим методом:

**Слой 1 — UX-структура (что где лежит и как течёт флоу).** Решается вайрфреймами и user flow до любого визуала. Обосновывается эвристиками юзабилити (10 эвристик Нильсена — видимость статуса системы, соответствие ожиданиям, предотвращение ошибок и т.д.) и паттернами, устоявшимися для данного типа продукта. У SFR этот слой уже частично закрыт: есть `SFR_Wireframes_Web.html`, флоу «лендинг → результаты → профиль», требования ≤3 клика и mobile-first из БФТ.

**Слой 2 — визуальное направление (характер: цвет, типографика, настроение).** Здесь практика такая: собирается мудборд из референсов, из него формулируются 2–3 контрастных направления (например «академично-строгое» vs «смелое молодёжное»), и выбор между ними делается не спором, а быстрым тестом на целевой аудитории (см. раздел 2). Это прямой аналог того, как в проекте выбирали платформу методом Борда — решение через процедуру, а не через вкус.

**Слой 3 — дизайн-система (из чего строить).** В 2026 для MVP почти никто не рисует компоненты с нуля: берут готовую компонентную библиотеку и кастомизируют её токены (цвета, шрифты, радиусы, отступы). Для стека Next.js де-факто стандартный выбор — связка **Tailwind CSS + shadcn/ui**: компоненты копируются в репозиторий (полный контроль кода, важно для соло-разработки с AI-агентами — агент правит компоненты напрямую), стиль легко перекрашивается токенами, доступность (a11y) встроена. Альтернатива Material UI оправдана для дата-тяжёлых админок, но даёт «гугловский» узнаваемый вид, который сложнее дифференцировать. Сравнение — у [Vercel](https://vercel.com/i/shadcn-vs-material-ui): shadcn/ui рекомендуют именно когда важна брендовая дифференциация и быстрая итерация; MUI — когда нужны готовые сложные таблицы.

**Слой 4 — проверка на пользователях.** Финальный слой: дешёвые быстрые тесты (5-секундный тест, preference test, reaction cards) до разработки и юзабилити-тесты на кликабельном прототипе после. Для студенческого проекта это ещё и генератор обоснований для паспорта.

Важная оговорка про «AI-генерацию дизайна»: в 2026 нормальная практика — генерировать варианты экранов AI-инструментами (v0, Claude и т.п.), но выбор между вариантами всё равно делается процедурой из слоёв 2 и 4, иначе это та же вкусовщина, только автоматизированная.

## 2. Чем обосновывать выбор (доказательная база)

Для паспорта и защиты пригодны три типа аргументов, по убыванию силы: собственное измерение → классическое исследование → отраслевой паттерн.

**Классические исследования (цитировать в обосновании):**

- **Первое впечатление формируется за ~50 мс** и определяется визуальной привлекательностью, а не контентом (Lindgaard et al., 2006, *Behaviour & Information Technology*, ~1000+ цитирований). Следствие: визуал лендинга — не «украшательство», а фактор конверсии первого шага воронки.
- **Aesthetic-usability effect** (NN/g): эстетичный интерфейс пользователи воспринимают как более удобный и прощают ему мелкие проблемы. Для MVP это аргумент вложиться в аккуратный визуал даже при урезанном функционале.
- **10 эвристик Нильсена** — стандартная рамка для аудита каждого экрана (статус системы, узнаваемость вместо припоминания, помощь при ошибках — это прямо про наши empty states при score < 0.27).

**Собственные измерения (сильнейший аргумент, в стиле проекта — «выбрано измерением, а не гипотезой»):**

- **5-секундный тест:** показать скриншот лендинга на 5 секунд, спросить «что это за сервис и для кого?» — проверяет, считывается ли ценностное предложение. Норма: ≥80% отвечают правильно.
- **Preference test двух направлений:** два варианта визуала → респондент выбирает + объясняет. N≈15–20 достаточно для уверенного сигнала при явной разнице.
- **Reaction cards (Microsoft Desirability Toolkit, [методика NN/g](https://www.nngroup.com/articles/microsoft-desirability-toolkit/)):** список ~25 слов (≥40% негативных: «скучный», «перегруженный», «казённый»… и позитивные: «понятный», «современный», «вызывает доверие»), респондент выбирает подходящие к макету, считаются проценты. Даёт числовую характеристику «как студенты воспринимают дизайн» — идеально ложится в отчёт 3 семестра.

Все три метода бесплатны, делаются в Google Forms за вечер и прогоняются на CustDev-сети (те же 10–15 студентов, что нужны для внешнего тест-сета запросов — можно объединить в один заход со Светой).

**Отраслевые паттерны (для конкретных экранов):** best practices страницы результатов поиска ([Halo Lab](https://www.halo-lab.com/blog/search-results-page-design/), [UXPin](https://www.uxpin.com/studio/blog/advanced-search-ux/)): для «контентно-тяжёлых» позиций — список, не сетка; показывать число найденных результатов; ≤10 фильтров, остальное под «ещё»; запрос остаётся видимым в строке поиска; empty state всегда предлагает альтернативу, а не тупик.

## 3. Что нравится студентам (Gen Z), и как к этому относиться

По трендовым обзорам ([Spicetree](https://spicetreedigital.com/blog/designing-websites-for-gen-z-what-works-in-2025), [Supercharged](https://www.supercharged.studio/blog/gen-z-design-trends), [Net-Craft](https://www.net-craft.com/blog/2026/01/16/gen-z-website-design-trends/)) устойчиво повторяются: смелая крупная типографика и высокий контраст вместо «корпоративной стерильности»; mobile-first как база, а не адаптация; скорость загрузки <3 сек (у нас в БФТ жёстче — ≤2 сек); микроанимации и живой отклик интерфейса; аутентичность и человеческий тон вместо канцелярита; доверительные сигналы — реальные отзывы, реальные люди; тёмная тема как ожидаемая опция.

**Честная оговорка (важно для обоснования):** это трендовые статьи агентств без приведённых данных — в паспорт их тащить как доказательство нельзя. Правильная конструкция: тренды дают *гипотезы направлений*, а *решение* принимает тест на наших студентах (раздел 2). Это ровно логика проекта: multi-source research + собственная верификация.

Специфика SFR, которую тренды не учитывают: наш продукт — про **доверие к академическому сервису**. Студент решает вопрос на годы (научрук), а не заказывает пиццу. Поэтому чистый «Gen Z bold» (неон, брутализм, мемы) рискует убить доверие, а чистый «академический официоз» — оттолкнуть скукой и «казёнными вузовскими сайтами» (антиреференс, знакомый каждому респонденту CustDev). Рабочая гипотеза — середина: **современный, лёгкий, но взрослый** дизайн уровня хороших российских продуктов, которыми студенты уже пользуются ежедневно (hh.ru, Т-Банк, Авито, Яндекс-сервисы): много воздуха, крупная типографика, 1 яркий акцентный цвет, скруглённые карточки, аккуратные микроанимации. Плюс наш differentiator — честная наукометрия с указанием источника («по данным OpenAlex») как сигнал доверия, по аналогии с ПроДокторов.

## 4. План для SFR (конкретика)

**Шаг Д1 — зафиксировать 2 направления-кандидата (1 вечер, можно с AI-генерацией макетов):**

- **Направление A «Научная свежесть»:** светлый фон, синий/индиго акцент (перекликается с палитрой МФТИ из дека v8 — бонус консистентности с питчем), шрифт типа Inter/Golos, строгие карточки, сдержанные анимации. Настроение: «Яндекс.Практикум для науки».
- **Направление B «Смелый кампус»:** более плотная типографика, контрастный тёплый акцент, крупные заголовки в тоне «найди своего научрука за минуту», больше графики/иллюстраций. Настроение: «стартап для своих».

**Шаг Д2 — тест на студентах (совместить со сбором внешних OOD-запросов, задача уже стоит на Борисе+Свете):** 5-секундный тест лендинга обоих направлений + preference test + reaction cards из ~25 слов. N = 12–20 из CustDev-сети. Выход: выбранное направление + проценты для отчёта («направление A выбрали 78%, топ-слова: понятный, современный, вызывает доверие»). *Статус 31.08: отложено до пилота, чеклист — `01_core/plan/TODO_Света_дизайн_и_юзер-тесты.md`.*

**Шаг Д3 — токены и дизайн-система:** shadcn/ui + Tailwind поверх Next.js; победившее направление кодируется в `tailwind.config` / CSS-токены (цвета, шрифт, радиусы) — дальше все экраны SFR-3 собираются агентом из этих компонентов автоматически консистентными. Тёмная тема — бесплатно из коробки shadcn.

**Шаг Д4 — UX-решения экранов (уже обоснованные, вносить в спеку SFR-3):**

| Экран | Решение | Основание |
|---|---|---|
| Лендинг | Один экран = одно действие: поле «опиши свои научные интересы» + пример запроса-плейсхолдер; ценность в заголовке за 5 сек | 50-мс эффект; 5-сек тест; ≤3 клика из БФТ |
| Результаты | Список (не сетка) карточек с % совпадения, число найденных, запрос виден и редактируем, ≤10 фильтров | Паттерны search UX (detail-heavy → список); референс: findaphd.com (счётчик, фильтры, сохранённый поиск) |
| Результаты | Serendipity-слот визуально помечен («неожиданный вариант») | Эвристика «видимость статуса», честность рекомендации + требование ст. 10.2-2 о прозрачности рекомендаций |
| Результаты (пилот) | Бейдж «открытая позиция» / «активный грант» на карточке — сигнал «НР реально ищет» важнее любого фильтра | v1.1: FindAPhD ставит тип финансирования первым фильтром, ApplyIndex — бейдж Active Grant; CustDev-инсайт |
| Empty state (score < 0.27) | Не тупик: «уверенных совпадений нет» + подсказка переформулировать + примеры удачных запросов | Паттерн empty state; эвристика помощи при ошибках |
| Профиль НР | Наукометрия с подписью «по данным OpenAlex», понятная иерархия: кто → чем занимается → как связаться; **страница открыта и индексируема** (SSR) | Доверие; юр. контур (источник данных); v1.1: антипаттерн ApplyIndex — каталог за логином убил органический канал (17 тыс. визитов/мес против ~0,5 млн у FindAPhD с 39% organic) |
| ЛК (пилот) | Статус переписки по каждому НР: не писал / написал / ответил / отказ / договорились | v1.1: паттерн ApplyIndex (CRM-dropdown); даёт нам измерение конверсии «подборка → заявка → ответ» |
| Всё | Mobile-first вёрстка, ≤2 сек загрузка, микроанимации умеренно | БФТ; Gen Z-гипотезы, проверенные тестом Д2 |

**Шаг Д5 — после сборки SFR-3:** юзабилити-прогон флоу на 5 студентах с телефона (уже стоит в DoD PoC) + heuristic-аудит по 10 эвристикам. Результаты обоих — в отчёт 3 семестра как «дизайн выбран и проверен измерением».

**Что это даёт учебному треку:** методологическая симметрия с остальным проектом — как модель эмбеддингов выбрана замером 5 кандидатов, а платформа методом Борда, так и дизайн выбран preference-тестом + reaction cards на целевой аудитории, с опорой на классические исследования (Lindgaard 2006, aesthetic-usability effect, эвристики Нильсена). Готовая формула для паспорта/отчёта: «решение → метод выбора → измеренный результат».
