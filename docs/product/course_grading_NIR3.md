# Критерии оценивания НИР 3 — трек «Стартап»

*Источник — ЛМС курса, раздел «Критерии оценивания» → «Стартап»; текст критериев перенесён дословно 30.09.2026. Изменится в ЛМС — обновить здесь с датой. График семестра — `course_plan_NIR3-4.pdf`; задачи — #73 (промежуточная презентация), #74 (замечания комиссии), #80 (отчёт и аттестация).*

## Из чего складывается оценка

Оценка за НИР в 3 семестре = **50 % промежуточная презентация + 50 % отчёт о личном вкладе**. Каждый критерий оценивается по 10-балльной шкале и умножается на коэффициент.

*Расчёт по коэффициентам (не текст ЛМС):* в итоговой оценке семестра индивидуальные критерии весят **0,9** (0,4 — в презентации, 0,5 — отчёт), групповые — **0,1** (проблема 0,025, УЦП 0,025, рабочая гипотеза 0,05).

## Промежуточная презентация — 50 %

Выступления оцениваются по критериям, описанным в таблице. Каждый критерий оценивается по 10-балльной шкале. Члены комиссии на выступлении могут прокомментировать слабые стороны по критериям, однако балльную оценку за каждый критерий не выдают.

| Критерий | Описание | Коэф. |
|---|---|---|
| **Групповые критерии** | | |
| Проблема | Есть описанная ключевая проблема: четко и коротко сформулированная боль потребителя в одном предложении. Студенты могут подтвердить значимость (актуальность) проблемы (в цифрах, с использованием источников данных) | 0,05 |
| УЦП | В формулировке четко понимается выгода для определенного сегмента ЦА, на котором пилотируется продукт. Есть обоснование, какое именно решение предлагается и почему оно закроет проблему ЦА | 0,05 |
| Гипотеза проекта (рабочая гипотеза проекта) | Гипотеза должна быть сформулирована таким образом, чтобы в ходе ее проверки можно было подтвердить релевантность уникального ценностного предложения (УЦП) | 0,1 |
| **Индивидуальные критерии** | | |
| Роль и задачи | Студент выполняет задачи, формирующие профессиональные компетенции по направлению подготовки, понимает их специфику. Работа обучающегося демонстрирует выполнение достаточного объема профильных задач, соответствующих его роли в проекте. Задачи самостоятельны, логически взаимосвязаны, соответствуют профилю обучения студента и направлены на достижение целей проекта | 0,2 |
| Гипотезы и проблемы (личная гипотеза обучающегося) | Гипотеза описана в четкой, ясной формулировке без неоднозначных трактовок и связана с описанной проблемой в рамках задач студента. Индивидуальная исследовательская гипотеза является декомпозицией рабочей гипотезы всего проекта в рамках роли в проекте. В гипотезе есть метрики в цифрах, которые являются критерием подтверждения/опровержения гипотезы и которые обоснованы с точки зрения теоретического анализа источников и проведенных исследований | 0,2 |
| Теоретический анализ | Есть анализ источников (связный теоретический обзор первичных и вторичных источников: проблемные интервью с клиентами, экспертные интервью, научные статьи, отчеты исследовательских организаций и другое) для постановки и проверки гипотезы. Из анализа очевидно, на основе какой полученной информации сформулирована гипотеза | 0,2 |
| Методика | Методика проверки гипотезы описана, студент может прокомментировать ее пошагово | 0,2 |

## Отчёт — 50 %

Ниже приведен блок оценивания, касающийся личного вклада участника и составляющий 50 % общей оценки за работу по НИР в 3 семестре. Остальные 50 % складываются из оценки студента, полученной на промежуточной презентации.

Обратите внимание, что невыполнение требований по читабельности, структурированности, наличию приложений и ссылок (необходимый файл не прикреплен или доступ к нему не открыт) свидетельствуют о нарушении формата или отсутствии обязательных материалов, что может стать причиной снижения оценки. Каждый критерий оценивается по 10-балльной шкале.

Не забудьте приложить к отчету обновленную презентацию, которую вы переработали, опираясь на результаты промежуточной презентации.

| Критерий | Описание | Коэф. |
|---|---|---|
| Профильность и полнота роли | Студент выполнил поставленные задачи, соответствующие его программе и роли в проекте: исследовательские и производственные. Объем и сложность задач соразмерны масштабу проекта и команде; экспертная оценка нагрузки работы за семестр — от 130 часов (только исследовательские и производственные задачи). Студент был активен и включен в течение семестра, взял ответственность за весомый блок работы | 0,2 |
| Релевантность и глубина теоретического анализа | Студент провел полноценный теоретический анализ и сформулировал проблемы, использовал первичные и вторичные источники, сопоставил подходы разных экспертов и исследований, выявил недостатки существующих решений и обосновал актуальность своей исследовательской задачи. Из анализа логично вытекает понимание планируемого инновационного вклада в сборку продукта | 0,2 |
| Релевантность исследовательской гипотезы | Гипотеза сформулирована однозначно и не допускает двояких прочтений, опровержима, нетривиальна, с указанием метрик (также формул их расчета, если они не общеприняты) и соответствует профессиональной роли студента. Она логично следует из теоретического анализа, делает вклад в создание УЦП продукта | 0,2 |
| Адекватность и воспроизводимость методики исследования | Описана методология (если используются несколько методов) и методика исследования (пошаговая репрезентация того, как будет выполнено исследование, с использованием каких данных, аргументацией подхода). Методика должна быть адекватна поставленной гипотезе и описана в достаточной мере, чтобы дать представление о шагах исследователя и их корректности | 0,2 |
| Полезность результатов исследования и производственных задач | Результаты проверки гипотезы подробно описаны, они делают значимый вклад в УЦП продукта. Выполнены другие значимые производственные задачи, не включенные в контур исследования, представлена их ценность | 0,2 |

## Что из этого следует для нас (анализ продуктового треда, 30.09.2026)

- **Оценка почти целиком индивидуальная (0,9).** У Бориса и у Светы — своя роль, своя личная гипотеза, свой теоретический анализ и своя методика; общая часть (проблема, УЦП, рабочая гипотеза) — 0,1.
- **Рабочая гипотеза проекта** должна быть сформулирована так, чтобы её проверка подтверждала релевантность УЦП. Ближе всего в документах — «Гипотеза продукта для пилотирования» (паспорт, лист 4, A102) и метрики успеха (`mvp_spec.md`, Часть 0, «Метрики успеха»).
- **Личных гипотез пока нет ни в одном документе.** Каждая — декомпозиция рабочей гипотезы по роли: однозначная, опровержимая, нетривиальная, с метриками в цифрах (и формулами, если метрика не общепринятая), обоснованная источниками и собственными исследованиями.
- **Роль и объём — от 130 часов** исследовательских и производственных задач за семестр. Учёт часов не ведётся; опора для отчёта — история issues, PR и коммитов. Код MVP в основном пишут автономные сессии Claude Code — в отчёте явно показать, что делал сам студент (постановка задач, исследовательский дизайн, метрики, приёмка результатов, решения), иначе критерий «задачи самостоятельны» может быть прочитан не в нашу пользу.
- **Приложения должны открываться у проверяющего** — «доступ не открыт» прямо назван причиной снижения. Репозиторий приватный: ссылки на GitHub комиссия не откроет — прикладывать файлами или через Google Drive.
- **К отчёту прикладывается переработанная презентация** — по замечаниям комиссии (#74).
- **Цифры качества** в презентации и отчёте — только из блока «Состояние» `docs/DECISIONS.md`, с условиями применимости; прежние 92 % / 75 % (мягкий судья) несравнимы и не используются.
