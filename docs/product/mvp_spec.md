## Часть 0. Рамка

### Цель MVP

Проверить главную продуктовую гипотезу: *студент, введя описание своих научных интересов, получает за минуту релевантную подборку научных руководителей из разных вузов — и это достаточно ценно, чтобы он отправил заявку НР (и заплатил).*

### Метрики успеха (из паспорта, гипотеза пилотирования)

| Метрика | Целевое значение | Статус на 29.08 |
|---|---|---|
| Релевантность мэтчей | ≥70% (хотя бы 1 из 5 НР соответствует) | **Достигнуто и измерено** на пилотном корпусе (SFR-1/2), на каталоге 12 вузов (SFR-5) и на боевом каталоге с потолком (SFR-5c). Действующие цифры с условиями применимости (слепой судья, наборы 24 и 22, интервал по спорным парам) — блок «Состояние» `docs/DECISIONS.md`; история измерений и почему цифры разных судей несравнимы — `docs/reports/SFR5c_REPORT.md` §13.11 |
| Время поиска НР | с 3–12 недель → до минуты | латентность поиска ~136 мс (CPU) — техническая часть ок; продуктовая — мерить на пилоте |
| Конверсия «подборка → заявка НР» | ≥25–30% у early adopters | пилот |
| Удовлетворённость (CSI) | ≥8/10, N≥30 | пилот |

Технические пороги из БФТ: отклик мэтчинга ≤10 сек (факт: <1 сек), загрузка страницы ≤2 сек, uptime ≥99%, ≤3 клика до результата, mobile-first.

### Две вехи

| Веха | Что доказывает | Срок |
|---|---|---|
| **PoC** | Мэтчинг технически работает и релевантен на реальных данных 2–3 вузов; кликабельный веб-флоу | план был «конец ноября»; при текущем темпе реалистично **конец сентября — октябрь 2026**. Освободившийся буфер — на расширение каталога (больше вузов) и калибровку порога, к отчёту 3 семестра приходим с запасом |
| **Пилот** | Продуктовая ценность: 100 студентов МФТИ/МГУ/ВШЭ, конверсия ≥25%, CSI ≥8 | без жёсткой даты; реалистично — зима 2026/27 (сдвиг влево против v1) |

### Рабочий процесс (зафиксирован по итогам SFR-0/SFR-1)

**С 12.09.2026 список работ итерации — issues с лейблом `agent` и текущим milestone на доске «SFR — задачи»; спека описывает «как», находки ревью идут в issues `from-review`, «требует человека» = лейбл `human` (правила — `CLAUDE.md` репо, раздел «Задачи — в GitHub Issues»).** Итерация = спека `SPEC_SFR<N>.md` в корне репо (после закрытия итерации — в `docs/specs/`; в репо от итерации остаются спека + отчёт, ревью и заметки временные) → автономная сессия Claude Code — длинная, запускается когда удобно Борису, днём или ночью (`--permission-mode auto`; сессия сама пушит свою ветку и открывает PR; push в `main`, merge и выкладка — только Борис, граница — хук `.claude/hooks/block-push.sh`) → человек проверяет отчёт `docs/reports/SFR<N>_REPORT.md` (§0 «Резюме для человека», честный DoD-чеклист, раздел «Правки паспорта») → push, PR, merge → следующая спека. Решения — `docs/DECISIONS.md` (блок «Состояние» и записи по датам); `docs/SESSIONS.md` заморожен 27.09.2026.

## Часть 1. Спека продукта MVP

### 1.1 Скоуп: что входит (Must + Should)

По MoSCoW из паспорта, с адаптацией под соло-разработку. Каждый компонент разбит на **PoC-версию** и **пилот-версию**.

#### C1. AI-движок мэтчинга (Must) — БФТ 1.1, 2.1 — ✅ ядро готово (SFR-1)

- **PoC:** ввод интересов (50–500 симв.) → embedding search → топ-5–10 карточек с % совпадения. Сделано как библиотека `sfr-match` + CLI; осталось обернуть в API (SFR-2).
- Модель: **ai-forever/FRIDA** (префиксы search_query/search_document, dim 1536). Запасная при проблемах с латентностью: paraphrase-multilingual-mpnet-base-v2 (95% Success@5, в 6,8 раза быстрее, в 3 раза меньше). Замер SFR-1: FRIDA 100%, mpnet 95%, e5-base 91%, BM25 41% (вклад лексики), MiniLM из раннего паспорта — 27%.
- **Уверенность выдачи — три уровня (SFR-4):** `none` (top-1 ниже порога отсечки) → «уверенных совпадений нет», выдача остаётся; `weak` (серая зона) → баннер «совпадения слабые, в базе, похоже, нет специалистов по теме» (введено после живого запроса про backend engineering: мусорная выдача без предупреждения); `ok` выше. Грейды карточек — словесные (высокое / среднее / слабое), процента нет нигде. Все границы принадлежат паре модель×индекс, живут в settings API и отдаются в `/health`; действующие значения — блок «Состояние» `docs/DECISIONS.md`, история калибровок — отчёты SFR-2, SFR-5, SFR-5c.
- **Пилот:** + RAG-объяснение мэтча (50–150 слов), фильтры по h-index.
- **Пилот, фича-эксперимент: serendipity-слот** (идея 29.08, родство с БФТ 2.4): один слот выдачи — «неожиданный вариант» из смежного кластера embedding-пространства (MMR/diversity re-ranking: достаточно близко для мостика, достаточно далеко чтобы удивить), с пометкой в UI. Обоснование: CustDev-инсайт «студент сам не до конца знает, чего хочет»; аналог serendipity в рекомендательных системах (Spotify). Метрика проверки: CTR/заявки серендипити-слота против обычных позиций. Коллаборативный слой («похожие студенты смотрели…») — этап 2, когда появятся данные поведения. Питч-формулировка: «не просто ищем — расширяем горизонт выбора».
- **Отложено на этап 2:** междисциплинарный режим (БФТ 2.4); **бейдж и фильтр «активный грант»** (v1.6: у аналогов это первый по важности фильтр — FindAPhD ставит тип финансирования выше дисциплины, ApplyIndex помечает профили «Active Grant»; для нас источник — открытый поиск проектов РНФ по руководителю; бейдж на карточке приоритетнее фильтра, т.к. работает и без авторизации); гибрид с BM25 (имеет смысл только с переводом запроса — вне MVP); коллаборативные рекомендации.

#### C2. Каталог профилей НР (Must) — БФТ 1.1 — ✅ конвейер готов (SFR-0), данные частично

- Профиль: ФИО, вуз, должность, h-index, число публикаций, темы, последние работы. Конвейер: OpenAlex → PostgreSQL/SQLite → profile_text → JSONL. Факт: 300 авторов МФТИ → 261 кандидат в НР → 6522 работы.
- **PoC:** 2–3 вуза, ~500–1000 профилей — ✅ 535 (SFR-0/1); в SFR-5 каталог доведён до 12 вузов.
- **Пилот:** 10+ вузов, ≥3000 профилей — ✅ **выполнено досрочно в SFR-5 (12 вузов, 5 538 профилей, 09.2026; с 26.09 — 9 002 с потолком на вуз, SFR-5c)**; поле «статус доступности» вручную.
- Известные проблемы данных (из SFR-0/SFR-1, чинить в следующих итерациях): расщеплённые/однофамильные профили (дедупликация по ORCID + пересечению работ); участники мегаколлабораций (ATLAS/CMS) — профиль не отражает личный вклад, понижать вес много-авторских работ; тематики OpenAlex иногда ошибочны. Чистка LaTeX-мусора: эффект на поиск ~0 (замерено), оставлена только для читаемости карточек.
- ⚠ Отклонение от паспорта: «≥5 000 НР из 50+ вузов» — цель полного MVP после пилота.

#### C3. Веб-приложение (Must) — БФТ ∞ — ✅ PoC-версия готова (SFR-3, 03.09)

Страницы (по вайрфреймам SFR_Wireframes_Web.html): `/` лендинг (онбординг БФТ 1.2 сведён к лендингу), `/results`, `/supervisor/:id`, `/profile` (пилот). Стек: Next.js (SSR → SEO), mobile-first, ≤3 клика.
**PoC:** ✅ страницы 1–3 без авторизации; открытые страницы НР индексируемы (SSR + ISR, sitemap 535, canonical/OG; Lighthouse SEO 100) — органический канал работает технически, осталось вывести на домен (SFR-4). **Пилот:** + авторизация, ЛК, статусы заявок; **сохранённый запрос + алерт «появились новые НР/позиции по вашему запросу»** (v1.6, паттерн FindAPhD email alerts: дешёвый retention, при пересборке каталога раз в семестр — письмо с новыми совпадениями; требует авторизации, поэтому пилот).

#### C4. Система отзывов о НР (Must) — БФТ 1+2 — пилот

- 5 критериев (1–10), текст 100–500 слов, анонимность по желанию. **PoC: не делаем** (некому оставлять).
- **Пилот:** форма + модерация; верификация ручная (OAuth *.edu.ru — этап 2), LLM-фильтр текста, порог показа ≥3 отзывов. Холодный старт: честные пустые состояния + seed 30–50 отзывов из сети CustDev.
- Ожидание по объёму (v1.6, из мирового опыта): отзывы — фича, а не ценность пилота; см. риск в §2.3.

#### C5. Модуль коммуникации (Should) — БФТ 2.2 — PoC-версия тривиальна

- **PoC:** кнопка «Показать email + шаблон письма» (copy-paste). **Пилот:** отправка через SMTP + трекинг статусов; 3 шаблона, проверенных у 2–3 действующих НР (задача Светы, стык с supply-side интервью). **Статус переписки по каждому НР** в ЛК (v1.6, паттерн ApplyIndex): не писал / написал / ответил / отказ / договорились — студент ведёт мини-CRM своих обращений; это же даёт нам измерение конверсии «подборка → заявка → ответ».
- Без модуля не измерить конверсию «подборка → заявка» — поэтому в скоупе несмотря на Should.
- ⚠ **Факт SFR-3: адресов email в каталоге нет** (OpenAlex их не отдаёт; у всех 535 профилей `email = null`). PoC-версия «показать email + шаблон» сейчас показывает шаблон и честное «email не найден в открытых источниках». **Решение 12.09 (Борис):** контакты собираем из открытых источников — ORCID (даёт ~6%), страницы вузов/кафедр, корреспондирующий автор в статьях (сборщик — задача бэклога, серая зона: без обхода техзащиты, с opt-out); параллельно НР получает кнопку «Это я» (claim, C6) и возможность исключить себя из сервиса. Для 5 тест-пользователей PoC — ручной поиск адреса. Пока адреса нет — шаблон письма, который студент отправляет сам. Без источника контактов конверсию «подборка → заявка» на пилоте не измерить.

#### C6. Supply-side: claim profile + открытая позиция от НР (Should, новый в v1.6) — пилот

- **Что:** научрук подтверждает профиль («это я», верификация через домен вуза — конструкция из action plan 18.05 и юр. ресерча) и получает право опубликовать **открытую позицию/тему**: «ищу студента на тему X» (заголовок, 2–5 предложений, формат — ВКР/аспирантура/стажировка, срок). Позиция индексируется той же моделью и попадает в выдачу мэтчинга **рядом с профилем** (карточка помечена «открытая позиция»).
- **Почему:** паттерн FindAPhD — единица контента «проект + именованный научрук» 25 лет живёт как единственная прибыльная модель в нише; для нас это (а) supply-side активация с понятной для НР выгодой, (б) будущая B2B-единица монетизации (у FindAPhD — £27–110 за объявление), (в) сигнал «НР реально ищет» — самый ценный фильтр для студента по CustDev.
- **PoC:** не делаем. **Пилот:** claim + форма позиции + модерация; 5–10 позиций от НР из supply-side интервью Светы как seed. **Этап 2:** позиции от лабораторий/кафедр (B2B-аккаунт), статистика откликов.
- Замещает пункт SFR_TODO П5 «БФТ: компонент „Supply-side активация" (email-триггер без ФИО + claim profile)» — тот же компонент, расширенный позицией; в паспорт вносится одной строкой БФТ (Часть 3, п. 11).

### 1.2 Что НЕ входит (граница скоупа)

Этап 2 (после пилота): банк тем ВКР (Could), борд задач, ТГ-бот, статусы с подписками, профили студентов (БФТ 3.1), грантовый режим, междисциплинарный мэтчинг, монетизация (пилот бесплатный; WTP — опрос + фейк-дор «оплатить 300 ₽»; реальные пилотные платежи при необходимости — как самозанятый). **Добавлено v1.6 (из опыта аналогов):** **лид-дашборд кафедры/вуза** — заявки студентов к НР данного вуза видны ответственному лицу (агрегированно + экспорт), это аналитика входящего спроса и главный аргумент B2G (паттерн FindAPhD «Enquire → institution dashboard»); **встраиваемый виджет поиска НР** для сайтов кафедр/СНО/СМУ (паттерн FindAPhD CONNECT) — канал дистрибуции и lock-in партнёров, этап 2–3, стык с GTM Светланы. **eLibrary — подтверждённое [ЧЁРНОЕ]** (юр. ресерч 08.2026: смежные права ст. 1334 ГК + прямой запрет автосбора в соглашении + риск ст. 272/272.1 УК) — только официальный договор/API, этап 2+. Парсинг открытых страниц вузов — [СЕРОЕ, приемлемо] без обхода техзащиты, этап 2 через «адаптеры источников» в sfr-etl.

**Отвергнуто по итогам ресерча аналогов (v1.6, не переоткрывать без новых данных):**
- **«Индекс абитуриента» и прогноз «вероятность фандинга N%»** (ApplyIndex a-index) — ложная точность: у нас нет ни истории приёма, ни выборки исходов. Показываем % совпадения интересов, а не шансы поступления.
- **Массовая автоматическая рассылка писем НР от имени студента** (ApplyIndex, ApplyKite) — для НР это спам (проверить на supply-side интервью, но ожидание однозначное), плюс юр. риск с e-mail, полученными парсингом. Наш C5 — шаблон + осознанная отправка одного письма — остаётся.
- **Каталог за регистрацией** (ApplyIndex: «0 supervisors found» без логина, 17 тыс. визитов/мес) — противоречит решению «карточки открыты» и убивает органический канал.

**Принцип монетизации (юр. ресерч, в. 13; решение от 29.08, рабочая версия): карточки НР открыты, сервис — за деньги.** Открыто и индексируемо: ФИО, вуз, наукометрия, темы (и так публичные данные; опора п. 8 ч. 1 ст. 6 + SEO-канал). Платно (на пилоте — за бесплатную регистрацию): AI-подбор под запрос с % совпадения, «похожие НР», AI-объяснение, отправка заявки с шаблоном и статусами. Логика: продаём не карточку, а выбор из тысяч за минуту — данные о НР и сейчас формально открыты, а платить студенты готовы (CustDev). Мировой опыт подтверждает вектор: в нише платят вузы/лаборатории (листинги, лиды, профили), B2C-подписки на поиск научрука везде остались микромасштабом — см. `Мировые_аналоги_…`, §3–4. **Открытый вопрос к пересмотру перед включением монетизации (обсудить со Светой, GTM):** не скрыть ли часть карточки за бесплатной регистрацией; полный платный доступ к самим профилям не делаем (юр. риск утраты защиты п. 8).

### 2.4 Юридический контур (по deep research 08.2026; проверить у практикующего юриста перед публичным запуском)

**Сейчас (PoC, без юрлица) — можно:** строить всё на OpenAlex (CC0); дев-данные на своих машинах/РФ-VPS; тестовый показ 5 пользователям без публичного запуска. Пилотные платежи, если дойдёт до реальных, — как самозанятый (НПД).

**До публичного пилота — обязательный минимум (это задачи в план пилота):** уведомление РКН о начале обработки ПД (подаётся ДО запуска; с 30.05.2025 обязательно почти для всех, включая самозанятых); политика обработки ПД на сайте; правила применения рекомендательных технологий с описанием алгоритма + контакты (ст. 10.2-2 149-ФЗ — наш AI-подбор подпадает; исполняется одной страницей); правила отзывов + премодерация + форма жалобы/досудебного удаления + хранение метаданных автора (анонимность наружу, идентифицируемость внутри); публичная оферта по ЗоЗПП для платных функций; кнопка «это я — редактировать/скрыть» с верификацией и процедурой рассмотрения обращений (10 раб. дней).

**Стратегическое, на проработку к пилоту/этапу 2:** регистрация сетевого СМИ — конструкция, на которой ПроДокторов выиграл вплоть до КС (п. 8 ч. 1 ст. 6); ООО — к B2B и инвестициям (и так в планах, грант ФСИ). Триггеры пересмотра: первое официальное требование учёного об удалении; любой интерес РКН; база >10 000 профилей (порог тяжести штрафов); планы платного доступа именно к профилям (не делать).

### 2.5 Что это даёт учебному треку

К отчёту 3 семестра: работающий PoC с опережением (закрывает «Разработка MVP»); ML-тест мэтчинга **уже выполнен** (отложенная задача 2 семестра закрыта: golden set 30 запросов, 616 судейских оценок, Success@5 100% предварительно) — готовый материал для отчёта и обновления паспорта; измеренное обоснование смены модели (MiniLM 27% → FRIDA 100%); фактура для финмодели.
