# SFR-3 — фронтенд: лендинг, результаты, открытая страница НР

_Написан вручную 2026-09-03 по итогам итерации SFR-3 (SPEC_SFR3.md). Не генерируется — правки вносить прямо сюда._

## Что собрано

`apps/web` — Next.js 16 (App Router, TypeScript), Tailwind v4 (токены дизайн-системы
v1 в `app/globals.css`), компоненты в стиле shadcn/ui (скопированы в репо и правятся
напрямую), lucide-react. Три страницы по макетам `apps/web/design/mockups/`:

- **`/`** — лендинг: hero с `SearchBox` (textarea 3–500 симв., та же валидация, что
  у API), превью подборки из трёх **реальных** профилей каталога, «Три шага»,
  полоса цифр (число профилей — живое, из `/api/health`), тёмная CTA-секция, футер.
- **`/results?q=`** — клиентская страница: запрос виден и редактируем (`QueryBar`),
  фильтры (вуз, h-index) и сортировка — клиентские над ответом `/match` (k=10),
  счётчик «Найдено N · M вуза», skeleton-карточки на время запроса, один reveal
  (fade + 8px, 200 мс), `EmptyResults` при `below_threshold` с тремя реальными
  примерами из `eval/queries.jsonl` (q01, q03, q13 — кликабельны), состояние ошибки
  сети с «Повторить». `noindex`.
- **`/supervisor/[id]`** — серверная страница (SSR + ISR 1 час): шапка с чипами тем,
  блок «NN% совпадение» только при переходе с результатов (`?score=`, клиентский
  островок), «Чем занимается», `WorksList` (названия — в первую очередь, аннотации
  свёрнуты в `<details>` — вывод SFR-2 о сигнале в названиях), `MetricsCard` с
  tooltip «по данным OpenAlex», `ContactCard` (email из данных или честное «не
  найден» + шаблон письма с автоподстановкой имени и свежей работы + копирование),
  `ClaimProfileLink` (mailto с author_id в теме). Мобайл — порядок блоков по макету.
- 404 и ошибка сети — в стиле `results-empty`; `/dev/states` — витрина состояний
  (в т.ч. serendipity, которого на живых данных пока нет — API флаг не выставляет).

API (в рамках §4, логика поиска не тронута): опциональные поля карточки
`cited_by_count`, `top_works`, `position`, `email`, `serendipity`;
`GET /api/supervisors` (пагинация для sitemap и превью); обогащение — офлайн-файл
`data/exports/cards.jsonl` (`make export-cards`), при отсутствии файла API работает
с пустыми полями. `position`/`email` в данных каталога отсутствуют → всегда `null`.

Инженерия: npm + lock, `.nvmrc` (Node 24 LTS), `make web-*`, отдельный CI-job web
(lint + typecheck + unit + build; сборка проходит **без** живого API), прокси
`/api/match` через route handler (внутренний адрес API не светится, CORS не нужен).

## SEO-проверки (§3)

- **SSR без JS**: `curl localhost:3100/supervisor/A5050048876` отдаёт полный HTML —
  имя, вуз, темы, наукометрия, `<title>Konstantin Vorontsov — МФТИ | Search for
  Research</title>`, description, canonical, Open Graph. Проверено e2e (`ssr.spec.ts`)
  и руками.
- **sitemap.xml**: 535 URL `/supervisor/*` + лендинг = все профили каталога
  (сверяется с `profiles_count` из `/api/health` в e2e).
- **robots.txt**: `Allow: /`, `Disallow: /results`, `/api/`, `/dev/`; ссылка на sitemap.
- **Lighthouse** (прод-сборка, localhost, Mac; числа локальные, не VPS):

|---|---|---|---|---|
| `/supervisor/[id]` | **100** (порог ≥90) | 94 | 96 | 100 |
| `/` | 100 | 96 | 96 | — |
| `/results` | 63¹ | 90 | 95 | — |

¹ `/results` намеренно `noindex` — Lighthouse за это штрафует; это подтверждение
настройки, а не дефект. Accessibility 96: контраст токена `--fg-subtle` (#9AA1B0)
на белом ниже WCAG AA для мелкого текста — свойство дизайн-системы, вопрос ниже.

## Латентность (локальный Mac, прод-сборка; на VPS будет иначе)

- TTFB `/supervisor/[id]`: ~20 мс первый рендер (ISR miss, включая запрос к API),
  ~2 мс из ISR-кэша.
- `/results`: время до карточек ≈ времени `/api/match` через прокси — p50 ~130 мс
  на прогретом API; первый запрос после долгого простоя — до ~3 с (прогрев пути
  модели). Skeleton-карточки закрывают ожидание; в контейнере на VPS ориентир
  из SFR-2 — ~0.6 с p50.

## Что не дотянуто (честно)

- **Serendipity виден только в `/dev/states` и тестах** — API флаг не выставляет
  (по спеке так и задумано, но пользователь этого состояния не увидит до SFR-4+).
- **Должности, степени, журналы изданий, «активен N работ за 3 года»** — в данных
  каталога этого нет; соответствующие места макета деградированы, не восполнены.
- **Email НР** — в OpenAlex его нет, ContactCard всегда показывает «не найден в
  открытых источниках». Блок работает, но своей главной ценности (адрес) не даёт,
  пока не появится источник контактов.
- **Шаблон письма — черновик**, не проверен НР/Светой (I10 паспорта обещает
  «шаблоны проверены 2–3 действующими НР» — это не про MVP, но помнить).
- **Lighthouse Performance измерен на локалхосте** — сеть нулевая; на реальном
  VPS числа будут ниже, перемерить в SFR-4.
- **`.env.example` не дополнен** (ограничение прав агента).
- **Расщеплённые профили** (долг SFR-0) заметны на страницах НР: у части авторов
  в работах чужие статьи. Фронт это не чинит и не маскирует.
