# SPEC GH-MIGRATION — перенос задач проекта в GitHub Issues + Projects

**Дата:** 12.09.2026 · **Автор спеки:** Борис + Claude · **Исполнитель:** сессия Claude Code в репо `search-for-research` (интерактивная, Борис рядом — есть две паузы на проверку)
**Репо:** `borisboriov/search-for-research`, **приватный** (с 12.09). Все задачи проекта — код, документы, продукт, Света — живут issues в этом одном репо.

---

## 0. Зачем и что должно получиться

Задачи стартапа размазаны по пяти markdown-файлам в двух папках (репо и папка документов) плюс проект Claude. У задач нет статусов, владельцев и фильтров; зеркалирование файлов даёт расхождения; Свете контекст приходится передавать пересылкой файлов.

После этой сессии:

1. В репо есть **лейблы**, **Milestones** (этапы продукта) и **Project «SFR — задачи»** (доска) с полями Status / Iteration / Priority.
2. **Все открытые задачи** из TODO-файлов перенесены в issues, каждая — со ссылкой на источник (файл и строка) и дословной цитатой; все issues добавлены на доску с заполненными полями.
3. Исходные md-файлы **не удалены и содержательно не изменены** — только одна строка-пометка в шапке «перенесено в GitHub Issues» (шаг 5, после подтверждения).
4. В репо появился `docs/GITHUB_WORKFLOW.md` — правила работы с issues для людей и ночных агентов, легенда итераций SFR-0…SFR-6 — и короткий блок-ссылка на него в `CLAUDE.md`.
5. Отчёт `docs/GH_MIGRATION_REPORT.md`: сколько задач откуда, что пропущено и почему, что осталось Борису руками.

**Ограничения.** Без `git push`. Не читать `.env`, `deploy/target.local`, `01_core/custDev/*`. Никаких персональных данных респондентов CustDev и email научруков в текстах issues (если в TODO есть имя респондента — заменить на «респондент Р<N>»). Цифры продукта в issues не переписывать «по памяти» — только цитировать источник. В папке документов ничего не создавать и не менять, кроме строки-пометки в шапке `SFR_TODO.md` и `01_core/plan/TODO_Света_дизайн_и_юзер-тесты.md` (шаг 5).

Прочитать источники и собрать **все открытые** задачи в одну таблицу `migration/inventory.md` (папка `migration/` — временная, в конце уходит в `docs/` или удаляется по решению Бориса).

Источники, в порядке чтения:

| # | Файл | Что брать | Что не брать |
|---|---|---|---|
| 1 | `TODO_BORIS.md` (репо) | раздел «Открыто» | архив внизу |
| 2 | `docs/NEXT.md` | пункты следующей итерации SFR-7 и бэклог дальше | описательный текст |
| 3 | последний `docs/SFR6_REPORT.md` | раздел «Что не дотянуто» / незакрытые пункты DoD | измерения |
| 4 | `<папка документов>/SFR_TODO.md` | все незакрытые `[ ]`, включая «Мелкие хвосты» и «Открытые решения» | «Закрыто недавно» |
| 5 | `<папка документов>/01_core/plan/TODO_Света_дизайн_и_юзер-тесты.md` | блоки 0, 1, 2 — незакрытые `[ ]` | блок 3 (закрыт) |
| 6 | `<папка документов>/01_core/grant/Гранты_конкурсы_акселераторы_2026-2027.md` | только дедлайны подач с датой (как задачи с due date) | описания программ |
| 7 | `<папка документов>/Search_for_research_project_brief.md`, раздел «Где мы сейчас», абзац «Открытые решения Бориса» | сверить, что всё оттуда уже есть из источников 1 и 4; чего нет — добавить | остальное |

Колонки таблицы: `id` (временный, M1…), `title` (короткая формулировка ≤80 знаков, глагол в начале), `labels`, `milestone`, `iteration`, `priority`, `source` (`файл:строка`), `quote` (дословная цитата исходной строки), `note` (сомнения агента: «возможно, уже сделано», «дубль M12», «непонятно, кому»).

Правила разбора:

- Одна строка `[ ]` — одна задача. Вложенные подпункты — в тело issue как чеклист, не в отдельные issues, если это шаги одной задачи.
- Задача, у которой источник говорит «сделано» или которая противоречит текущему состоянию (например, «купить VPS» при работающем сайте) — в таблицу с `note: похоже, закрыто`, issue не создавать без подтверждения.
- Дубли между файлами (одна задача в TODO_BORIS и SFR_TODO) — одна строка, оба источника через `;`.
- Ничего не додумывать. Если формулировку невозможно превратить в задачу («подумать про монетизацию»), лейбл `decision` и заголовок «Решить: …».
- Отдельно вынести список «Известные расхождения»: где файлы противоречат друг другу или брифу (например, TODO Светы пишет «репозиторий публичный — ссылки открываются без входа», а репо теперь приватный → задача `sveta`: добавить Свету collaborator и поправить формулировку).

**Показать таблицу Борису и остановиться.** Борис вычёркивает, правит формулировки, отвечает на `note`. Дальше — только после его «ок».

### 4.3 Project «SFR — задачи»

```bash
gh project create --owner @me --title "SFR — задачи" --format json   # запомнить number
gh project link <number> --owner @me --repo borisboriov/search-for-research
```

Поля (`gh project field-create <number> --owner @me --name ... --data-type SINGLE_SELECT --single-select-options "..."`):

- **Status** (встроенное): оставить `Todo / In Progress / Done`, добавить `Backlog` первым и `Waiting` (ждёт человека/внешнего) — если через CLI не редактируется, записать в отчёт как ручной шаг Бориса.
- **Iteration** (single select): `SFR-7 · Ранжирование`, `SFR-8 · (следующая)`, `Без итерации`. Формат имени итерации — всегда «код · слово».
- **Priority** (single select): `P0 — блокирует`, `P1 — эта итерация`, `P2 — потом`.

Представления (views) через CLI не создаются — в отчёте написать Борису три вью, которые стоит сделать руками за две минуты: «Доска» (board по Status), «Мои руки» (table, фильтр `label:human`), «Света» (table, фильтр `label:sveta`).

## 5. Шаг 3 — создание issues и наполнение доски

Для каждой строки инвентаря, одобренной Борисом:

```bash
gh issue create --title "<title>" --label "<кто>,<область>" --milestone "<milestone>" --body-file migration/bodies/M<id>.md
```

Тело issue — шаблон:

```
## Что сделать
<формулировка задачи 1–3 предложения; если были подпункты — чеклист>

## Откуда
`<файл>:<строка>` — «<дословная цитата>»
(если несколько источников — все)

## Контекст
<1–2 предложения: почему это нужно / что блокирует; ссылки на docs/SFR<N>_REPORT.md, спеку, бриф — относительными путями в репо, для папки документов — имя файла без пути>

## Критерий готовности
<как понять, что закрыто; для agent-задач — измеримо>
```

Затем добавить на доску и выставить поля:

```bash
gh project item-add <number> --owner @me --url <issue-url>
gh project item-list <number> --owner @me --format json      # получить item id
gh project item-edit --project-id <PVT_id> --id <item-id> --field-id <field-id> --single-select-option-id <opt-id>
```

Id полей и опций — один раз через `gh project field-list <number> --owner @me --format json`. Скрипт для этого положить в `migration/set_fields.sh`, чтобы Борису можно было прогонять его повторно.

Правила по умолчанию для полей: `agent` + SFR-7 → Status `Todo`, Iteration `SFR-7 · Ранжирование`, Priority `P1`; всё `human`/`sveta`/`decision` с milestone «Пилот 5 тестеров» → `Todo`, `P1`; остальное → `Backlog`, `P2`, `Без итерации`. Отклонения — из колонки `priority` инвентаря после правок Бориса.

Порция: создавать по 10 issues, после каждой — `gh issue list --limit 100 | wc -l` для контроля. Rate limit GitHub — не проблема на ~50–80 issues, но паузу 1–2 с между вызовами держать.

## 7. Шаг 5 — пометка исходников и правила (после ПАУЗЫ 2)

### 7.1 Строка-пометка в шапке (единственная правка md)

В первую строку после заголовка каждого файла-источника (`TODO_BORIS.md`, `docs/NEXT.md`, `SFR_TODO.md`, `TODO_Света…` на диске):

```
> ⚠ 12.09.2026: задачи перенесены в GitHub Issues (доска «SFR — задачи»: <url>). Этот файл — архив, не редактировать; новые задачи — `gh issue create` или кнопка New issue.
```

Содержимое ниже не трогать. Зеркало TODO Светы в проекте Claude — Борис обновит сам (пометить в отчёте).

### 7.2 `docs/GITHUB_WORKFLOW.md` — новый файл

Разделы:

1. **Где что.** Задачи — issues; статус и приоритет — доска; знания — md в `docs/` (спеки, отчёты, DECISIONS, SESSIONS); статус проекта — бриф «Где мы сейчас». TODO-файлы — архив.
2. **Лейблы и milestones** — таблицы из §4.1–4.2 с пояснением «один „кто“, один-два „область“, один milestone».
3. **Именование итераций.** Код `SFR-<N>` остаётся ключом (лейбл ветки/коммита/спеки), но у каждой итерации есть слово: доска — `SFR-7 · Ранжирование`, спека — `SPEC_SFR7_ranking.md`, отчёт — `docs/SFR7_REPORT.md`. **Легенда закрытых:** SFR-0 данные и каталог PoC · SFR-1 поиск и выбор модели (FRIDA) · SFR-2 API и пороги · SFR-3 фронт по дизайн-системе v1 · SFR-4 compose, Caddy, деплой · SFR-4b аудит безопасности в CI · SFR-5 каталог 12 вузов, 5 538 профилей, перекалибровка порогов · SFR-6 дизайн-направление B, выкладка на search-for-research.ru. (Агент сверяет легенду с `docs/SESSIONS.md` и `docs/specs/`; расхождения — в отчёт, не править молча.)
4. **Правила для ночного агента** (этот блок дословно копируется в спеки итераций и в `CLAUDE.md`):
   - Перед началом: `gh issue list --label agent --milestone "<текущий>" --state open` — это и есть список работ итерации; спека уточняет **как**, issues — **что**.
   - Коммит, закрывающий задачу, содержит `Closes #N` в теле; не закрывать issue вручную без коммита.
   - Новая находка по ходу работы → `gh issue create` с лейблом `agent` + область, если можно сделать в этой же сессии по спеке — делать и закрывать; иначе оставить открытым. Требует человека → лейбл `human`. **Не создавать issue на то, что уже есть** (сначала `gh issue list --search`).
   - Находки ревью (`/review-iteration`) → issues с лейблом `from-review` вместо §0 следующей спеки.
   - Агент **не меняет** milestones, лейблы `sveta`/`decision`, приоритеты и не удаляет issues.
   - `TODO_BORIS.md` больше не ведётся: «требует человека» = issue `human`.
5. **Правила для Бориса и Светы** — доска, фильтры «Мои руки» / «Света», комментарий в issue вместо пересылки файла, закрытие задачи = Status Done; новая задача — New issue с лейблами, остальное подтянется.
6. **Шпаргалка `gh`**: list по лейблу, create, close, comment, view.

### 7.3 `CLAUDE.md` репо

Добавить короткий блок «Задачи — в GitHub Issues» (5–7 строк) со ссылкой на `docs/GITHUB_WORKFLOW.md` и четырьмя правилами из п. 4 выше в одну строку каждое. Упоминания `TODO_BORIS.md` в `CLAUDE.md` заменить на «issues `label:human`». Другие правила не трогать.

### 7.4 Коммит (без push)

`git add docs/GITHUB_WORKFLOW.md CLAUDE.md TODO_BORIS.md docs/NEXT.md migration/` → один коммит `chore: задачи перенесены в GitHub Issues + Project «SFR — задачи»` с трейлерами по правилам репо. Push — Борис сам после чтения отчёта.
