## Границы и предварительно заданный метод

Действующий индекс проверяется по метаданным и fingerprint корпуса, с опорой
на [доказательства выкладки 03.10](ui-analytics-deploy-20261003.md).
Каталог, эмбеддинги, API, интерфейс, инфраструктура и продуктовые документы
не меняются. Национальная выгрузка не используется. Исходники и контакты
хранятся вне git. Опросы и отправка писем не выполняются.

Выборка: восемь профилей каждого из 12 вузов по убыванию h-index, затем
четыре следующих среди оставшихся. Равенство разрешается по author_id.
Принадлежность — из docs.json проверенного индекса; один author_id один раз.
Настройка: первый профиль каждого из первых десяти вузов в порядке ID вуза;
эти ID фиксируются до запросов. Остальные 90 — проверка зафиксированного метода.
Это приоритетная выборка, не оценка доли принимающих студентов и не рейтинг НР.

Источники по порядку: структурированный ORCID без LLM → официальные страницы
человека/подразделения, темы и защищённые ВКР → координатор при отсутствии
личного контакта → дополнительные объявления. Поиск работы со студентами
продолжается после нахождения email. Crossref повторно не опрашивается.

Каждое утверждение: поле, значение/статус, объект и его тип, URL,
подтверждающий фрагмент, дата сведений (null при неизвестной), дата проверки,
исходное предложение для перепубликации, основания личности, проверяющий
и затраченное время. Статусы: found, not_found, not_checked, inaccessible,
contradiction, explicit_negative. Сырые кандидаты не считаются достоверными.

## Принятые критерии и независимая проверка v2

Критерии приняты Борисом 09.10 в продуктовом потоке
`01a11cb7-9131-7733-8047-4810c3020663`; повторного согласования не требуется.
Подробная [рубрика v2](../experiments/enrichment_verifier_v2.md).
Личность: имя и независимое совпадение работы/DOI или аффилиации;
конфликт блокирует привязку. ORCID из OpenAlex сам по себе не подтверждение.
Личная почта должна явно принадлежать человеку. У координатора отдельно
подтверждаются роль, область ответственности и связь подразделения с учёным.
Набор и готовность: только прямой текст с объектом и датой; история руководства
не равна текущему набору. Срок истёк — историческое предложение, дата неизвестна —
свежесть неизвестна. Нет суммы — оплата неизвестна.

Все контакты и утверждения о наборе проверяются по первоисточнику.
После сбора дополнительно проверяются первые 10 evaluation-профилей без
принятых утверждений в порядке author_id; при меньшем числе — все.
Проверка агентом и человеком учитывается отдельно. Борису передаётся таблица
первых десяти с основаниями; поле human_reviewed не заполняется агентом.
Изменения метода после просмотра 90 требуют нового номера метода и отдельного
экспериментального результата.

## Лимиты и доступ

ORCID: один record на профиль, глобально 1 запрос/с, максимум 150 запросов
данных на весь эксперимент, кэш без повторного запроса при перезапуске.
403/429 останавливают источник; 5xx допускает до двух повторов с backoff,
повторы тоже расходуют лимит. После пилота лимит поднят со 100 до 150 из-за
10 транспортных отказов; 90 ещё не смотрели. Исходная проверка правил сохранена,
новая — `orcid-rules-v1-pilot.json`. HTTP-ошибка не считается отсутствием данных.
Для сайтов: до четырёх поисковых запросов и восьми страниц на профиль,
включая вложения; до двух последовательных запросов/с глобально и одного/с
на домен, с учётом более строгого Crawl-delay. Перед доступом — robots.txt
и условия конкретного источника; неизвестные условия требуют разбора,
защиты не обходятся. Банк источников фиксирует все 12 вузов, найденные связанные
подразделения, назначение, принадлежность, дату и статус доступа.

[Квоты ORCID](https://info.orcid.org/ufaqs/what-are-the-api-limits/): анонимный
доступ 12 req/s и 25 000 reads/day на IP. Проверка 08.10.2026; общий расход IP
не известен, поэтому 429 останавливает прогон.
[Условия Public API](https://info.orcid.org/public-client-terms-of-service/)
ограничивают использование; этот исследовательский прогон не разрешает
перенос данных в коммерческий продукт.

## Проверка загрузчиков

Базовый существующий транспорт — httpx, как в contacts_experiment.py;
извлечение HTML — без LLM. Crawl4AI сравнивается на тех же зафиксированных
страницах: текст, ссылки, даты, таблицы, вложения, настройка, время и ручные
исправления. Отдельно различаются загрузка сайта и обработка сохранённого HTML.

[Crawl4AI](https://docs.crawl4ai.com/core/quickstart/) запускает Chromium и
преобразует HTML в Markdown; внешняя LLM для этого не нужна.
[Firecrawl](https://docs.firecrawl.dev/features/scrape) и
[Scrapy](https://docs.scrapy.org/en/latest/topics/downloader-middleware.html)
сравниваются только по документации и ожидаемым затратам, без вывода о качестве.
Платные API, подписки и внешние LLM не подключаются.

повтор использовал `CRAWL4_AI_BASE_DIRECTORY` внутри папки доказательств.

Firecrawl не запускался. По [документации](https://docs.firecrawl.dev/features/scrape)
обычная страница стоит 1 кредит, JSON добавляет 4, PDF тарифицируется по страницам.
При лимите 800 HTML-страниц это до 800 базовых кредитов без поиска, повторов и PDF;
JSON для всех — до 4 000. [Тарифы, проверка 08.10](https://www.firecrawl.dev/pricing):
1 000 бесплатных кредитов/месяц; Hobby 5 000 за $19/месяц при месячной оплате.
Платный вариант не нужен для текущего этапа и не подключён; если появится
отдельный прогон, предложение для решения — до 800 страниц и потолок $19
за месяц с отключённым автоматическим докупанием, без JSON/LLM.
Качество Firecrawl не измерено, бесплатный тариф также не подключался.

Scrapy не запускался. [AutoThrottle](https://docs.scrapy.org/en/latest/topics/autothrottle.html)
учитывает DOWNLOAD_DELAY и ограничения параллельности; robots надо включить

поддержка разметки сайтов, кэш, обработка дат и вложений. Оценка для планирования,

## Воспроизводимый запуск

В собственной ветке из корня worktree, после `uv sync --locked --all-packages`:

```bash
ENRICHMENT_ROOT=/private/tmp/sfr-enrichment100-evidence-20261008
SOURCE_DATA=/Users/boris/Projects/search-for-research/data
uv run python scripts/enrichment_experiment.py freeze \
  --index "$SOURCE_DATA/indexes_sfr5c/frida_clean" \
  --db "$SOURCE_DATA/sfr5c.db" \
  --deployment-proof docs/metrics/ui_analytics_deploy_20261003.json \
  --out "$ENRICHMENT_ROOT"
uv run python scripts/enrichment_experiment.py orcid \
  --root "$ENRICHMENT_ROOT" --cohort pilot \
  --mailto "$OPENALEX_MAILTO" --rules "$ENRICHMENT_ROOT/orcid-rules-v1-pilot.json"
uv run python scripts/enrichment_experiment.py prepare-review \
  --root "$ENRICHMENT_ROOT" --catalog-export "$SOURCE_DATA/exports/profiles_sfr5c.jsonl"
uv run python scripts/enrichment_experiment.py summary --root "$ENRICHMENT_ROOT"
uv run python scripts/enrichment_experiment.py export-metrics \
  --root "$ENRICHMENT_ROOT" --out /private/tmp/enrichment100-summary-new.json
```

`freeze` запускать только для нового эксперимента: существующий manifest
не перезаписывается. В этом эксперименте повторно используется готовая выборка.
`orcid` при повторе не отправляет запросы для уже записанных результатов;
`--retry-transport` явно повторяет только ConnectError и сохраняет предыдущие
результаты. 403/429 создаёт сохраняемую остановку источника, повторный запуск
её не снимает. После исчерпания 150 попыток запросы прекращаются.
Дата/URL/статус допуска ORCID находятся в `orcid-rules.json` вне git; перед
новым сбором надо заново проверить действующие правила. Mailto задаётся
из существующей настройки, credentials в worktree не копируются.

Для повторения экстракции, новый выходной каталог, отдельная среда:

```bash

uv pip install --python /private/tmp/sfr-enrichment100-crawl-venv/bin/python crawl4ai==0.9.4
CRAWL4_AI_BASE_DIRECTORY="$ENRICHMENT_ROOT/crawl-cache" \
  /private/tmp/sfr-enrichment100-crawl-venv/bin/python scripts/enrichment_compare_pages.py \
```

Пока реализованы заморозка, ORCID, подготовка проверки и офлайн-экстракция.
Универсального сборщика официальных сайтов/координаторов/объявлений нет.
Команда evaluation требует `--method-lock`: хеши выборки, полного разбора 10 и
кода/рубрики. Изменение метода после фиксации требует новой версии; согласие
Бориса с критериями уже получено. Человеческие решения остаются pending.

## Этап v2: исполняемый файловый адаптер и просмотр человеком

Добавлена роль `.codex/agents/sfr-enrichment-verifier.toml`, не меняющая
существующих судью и технического ревьюера. В текущем рантайме новая именованная
роль ещё не загружена: используется разрешённый отдельный native-субагент с
точными проектными инструкциями и `fork_turns=none`. Фактические model/effort
проверяются по собственному `turn_context`: gpt-6.1-sol / medium; переопределений
нет. Отсутствующие метаданные должны быть null, а не предположением.

Сборщик создаёт атомарные утверждения; `prepare` фиксирует профиль, исходное
извлечение, SHA выборки/извлечения/рубрики и бюджет. Агент получает этот вход,
самостоятельно ищет в интернете и возвращает JSON через частный spool.
`import` проверяет SHA, происхождение, независимость, все утверждения/18 полей,
доказательства и лимиты. Результат сохраняется отдельно и не заменяет извлечение.
`packet` строит автономный HTML/Markdown: карточка, оба набора утверждений,
ссылки/цитаты, пропуски и вопросы. `metrics` экспортирует только безопасный whitelist.
Файловый транспорт позволяет впоследствии подключить другой исполнитель, в том
числе API, без изменения схемы; сейчас API и постоянный сервис не подключены.

```bash
python scripts/enrichment_verification.py prepare --root "$ENRICHMENT_ROOT" \
  --collector /private/tmp/collector.json --version v2 \
  --rubric docs/experiments/enrichment_verifier_v2.md
# Координатор запускает отдельный native-агент по роли на полученном входе;
# агент возвращает результат в private spool, без записи в исходники.
python scripts/enrichment_verification.py import --root "$ENRICHMENT_ROOT" \
  --input "$ENRICHMENT_ROOT/verification/v2/inputs/AUTHOR_ID.json" \
  --result /private/tmp/verifier-result.json --run-id native-v2
python scripts/enrichment_verification.py packet --root "$ENRICHMENT_ROOT" \
  --inputs "$ENRICHMENT_ROOT/verification/v2/inputs" --run-id native-v2 \
  --ids ID1 ID2 ID3 ID4 ID5 --name packet-1
python scripts/enrichment_verification.py metrics --root "$ENRICHMENT_ROOT" \
  --version v2 --run-id native-v2 --out /private/tmp/safe-aggregates.json
python scripts/enrichment_protocol.py --root "$ENRICHMENT_ROOT" \
  --version v2 --run-id native-v2
```

Повторный запуск `prepare/import/packet` сохраняет совпадающий артефакт, а при
различии отклоняется. Новый результат требует нового run-id/версии. Лимиты
4 поиска/8 страниц применяются отдельно к каждому проходу; суммарная стоимость
двух проходов не выдаётся за стоимость одного. Неизвестные время/расходы — null.
Новый платный API и внешняя LLM: не используются; стоимость подписанной сессии
агентов инструментом не раскрывается и не объявляется нулевой.

Перед 90 `method-lock.json` фиксирует код/рубрику, SHA десяти входов и результатов.
Для человеческого контроля заранее задана случайная часть: пять из 90,
seed 19319420261009, сортировка author_id. Целевая часть отдельно: до трёх
расхождений/рисков и до трёх случаев без подтверждённых положительных утверждений,
по author_id, без пересечения со случайной частью. Недостающая страта не заменяется.
Причина каждого отбора сохраняется; статистика двух частей не объединяется.
Все human_reviewed/вердикты/минуты до реального просмотра человеком false/null.
Агентское подтверждение не является человеческим эталоном или продуктовой приёмкой.

Новые доказательства: `v2/` и `verification/v2/` вне git рядом с неизменяемым v1.
Первичная проверка правил у части контрольных URL выполнена после чтения
поискового кэша: журнал явно фиксирует это ограничение, а не утверждает проверку
до доступа. Последующие прямые загрузки без допуска не выполняются. Полное
сравнение транспорта/таблиц/вложений и результаты 90 ещё не завершены.

### Возобновление и доказательства передачи

Freeze и фиксацию метода повторять в существующей папке нельзя. Сборщик
сохраняет канонические JSON отдельно; prepare сохраняет снимок по SHA,
проверяющий получает профиль/атомы/исходные материалы/границы без ожидания автора.
Нативный запуск — ограниченное поручение независимому контексту по проектной
рубрике; существующие задания и runtime/тайминги сохранены вне git. У адаптера
запуска можно заменить файловый транспорт на API, но API не подключён.
Импорт выполняет валидацию и сохраняет отдельную версию. Пример для нового
готового результата и пакета (ID/пути берутся из фиксированных manifests):

```bash
uv run python scripts/enrichment_verification.py import \
  --root "$ENRICHMENT_ROOT" \
  --input "$ENRICHMENT_ROOT/verification/v2_complete_r2/inputs/$AUTHOR_ID.json" \
  --result "$VERIFIER_RESULT" --run-id "$NEW_RUN_ID"
uv run python scripts/enrichment_verification.py packet \
  --root "$ENRICHMENT_ROOT" \
  --inputs "$ENRICHMENT_ROOT/verification/v2_complete_r2/inputs" \
  --run-id "$NEW_RUN_ID" --ids "$AUTHOR_ID" --name "$NEW_PACKET"
uv run python scripts/enrichment_verification.py metrics \
  --root "$ENRICHMENT_ROOT" --version v2_complete_r2 \
  --run-id native-v2-complete --out /private/tmp/enrichment100-new-aggregate.json
uv run python scripts/enrichment_source_metrics.py \
  --root "$ENRICHMENT_ROOT" --version v2_complete_r2 --run-id native-v2-complete \
  --private-out /private/tmp/enrichment100-new-source-map.json \
  --safe-out /private/tmp/enrichment100-new-source-aggregate.json
```

При повторе те же source/input/output байты проверяются на равенство; новый
научный поиск требует отдельной версии результатов, старое не перезаписывается.
Самостоятельный поиск показан для всех десяти пилотных входов и 90 проверочных,
его запросы/URL/отказы и происхождение сохранены. Воспроизводима обработка
снимков, а не точное повторение меняющейся поисковой выдачи или агентских решений.

78 unittest и 388 pytest, 8 пропущены (Postgres), 5 deselected, coverage 94,06%.
