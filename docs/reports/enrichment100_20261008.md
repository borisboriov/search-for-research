## Границы и предварительно заданный метод

Действующий индекс проверяется по метаданным и fingerprint корпуса, с опорой
на [доказательства выкладки 03.10](ui-analytics-deploy-20261003.md).
Каталог, эмбеддинги, API, интерфейс, инфраструктура и продуктовые документы
не меняются. Национальная выгрузка не используется. Исходники и контакты
хранятся вне git. Опросы и отправка писем не выполняются.

Выборка: восемь профилей каждого из 12 вузов по убыванию h-index, затем
четыре следующих среди оставшихся. Равенство разрешается по author_id.
Принадлежность — из docs.json проверенного индекса; один author_id один раз.
Настройка: первый профиль каждого из первых десяти вузов в порядке ID вуза;
эти ID фиксируются до запросов. Остальные 90 — проверка зафиксированного метода.
Это приоритетная выборка, не оценка доли принимающих студентов и не рейтинг НР.

Источники по порядку: структурированный ORCID без LLM → официальные страницы
человека/подразделения, темы и защищённые ВКР → координатор при отсутствии
личного контакта → дополнительные объявления. Поиск работы со студентами
продолжается после нахождения email. Crossref повторно не опрашивается.

Каждое утверждение: поле, значение/статус, объект и его тип, URL,
подтверждающий фрагмент, дата сведений (null при неизвестной), дата проверки,
исходное предложение для перепубликации, основания личности, проверяющий
и затраченное время. Статусы: found, not_found, not_checked, inaccessible,
contradiction, explicit_negative. Сырые кандидаты не считаются достоверными.

## Критерии для согласования

Личность: имя и независимое совпадение работы/DOI или аффилиации;
конфликт блокирует привязку. ORCID из OpenAlex сам по себе не подтверждение.
Личная почта должна явно принадлежать человеку. У координатора отдельно
подтверждаются роль, область ответственности и связь подразделения с учёным.
Набор и готовность: только прямой текст с объектом и датой; история руководства
не равна текущему набору. Срок истёк — историческое предложение, дата неизвестна —
свежесть неизвестна. Нет суммы — оплата неизвестна.

Все контакты и утверждения о наборе проверяются по первоисточнику.
После сбора дополнительно проверяются первые 10 evaluation-профилей без
принятых утверждений в порядке author_id; при меньшем числе — все.
Проверка агентом и человеком учитывается отдельно. Борису передаётся таблица
первых десяти с основаниями; поле human_reviewed не заполняется агентом.
Изменения метода после просмотра 90 требуют нового номера метода и отдельного
экспериментального результата.

## Лимиты и доступ

ORCID: один record на профиль, глобально 1 запрос/с, максимум 150 запросов
данных на весь эксперимент, кэш без повторного запроса при перезапуске.
403/429 останавливают источник; 5xx допускает до двух повторов с backoff,
повторы тоже расходуют лимит. После пилота лимит поднят со 100 до 150 из-за
10 транспортных отказов; 90 ещё не смотрели. Исходная проверка правил сохранена,
новая — `orcid-rules-v1-pilot.json`. HTTP-ошибка не считается отсутствием данных.
Для сайтов: до четырёх поисковых запросов и восьми страниц на профиль,
включая вложения; до двух последовательных запросов/с глобально и одного/с
на домен, с учётом более строгого Crawl-delay. Перед доступом — robots.txt
и условия конкретного источника; неизвестные условия требуют разбора,
защиты не обходятся. Банк источников фиксирует все 12 вузов, найденные связанные
подразделения, назначение, принадлежность, дату и статус доступа.

[Квоты ORCID](https://info.orcid.org/ufaqs/what-are-the-api-limits/): анонимный
доступ 12 req/s и 25 000 reads/day на IP. Проверка 08.10.2026; общий расход IP
не известен, поэтому 429 останавливает прогон.
[Условия Public API](https://info.orcid.org/public-client-terms-of-service/)
ограничивают использование; этот исследовательский прогон не разрешает
перенос данных в коммерческий продукт.

## Проверка загрузчиков

Базовый существующий транспорт — httpx, как в contacts_experiment.py;
извлечение HTML — без LLM. Crawl4AI сравнивается на тех же зафиксированных
страницах: текст, ссылки, даты, таблицы, вложения, настройка, время и ручные
исправления. Отдельно различаются загрузка сайта и обработка сохранённого HTML.

[Crawl4AI](https://docs.crawl4ai.com/core/quickstart/) запускает Chromium и
преобразует HTML в Markdown; внешняя LLM для этого не нужна.
[Firecrawl](https://docs.firecrawl.dev/features/scrape) и
[Scrapy](https://docs.scrapy.org/en/latest/topics/downloader-middleware.html)
сравниваются только по документации и ожидаемым затратам, без вывода о качестве.
Платные API, подписки и внешние LLM не подключаются.

## Воспроизводимый запуск

В собственной ветке из корня worktree, после `uv sync --locked --all-packages`:

```bash
ENRICHMENT_ROOT=/private/tmp/sfr-enrichment100-evidence-20261008
SOURCE_DATA=/Users/boris/Projects/search-for-research/data
uv run python scripts/enrichment_experiment.py freeze \
  --index "$SOURCE_DATA/indexes_sfr5c/frida_clean" \
  --db "$SOURCE_DATA/sfr5c.db" \
  --deployment-proof docs/metrics/ui_analytics_deploy_20261003.json \
  --out "$ENRICHMENT_ROOT"

  --root "$ENRICHMENT_ROOT" --cohort pilot \
  --mailto "$OPENALEX_MAILTO" --rules "$ENRICHMENT_ROOT/orcid-rules-v1-pilot.json"

  --root "$ENRICHMENT_ROOT" --catalog-export "$SOURCE_DATA/exports/profiles_sfr5c.jsonl"

uv run python scripts/enrichment_experiment.py export-metrics \
  --root "$ENRICHMENT_ROOT" --out /private/tmp/enrichment100-summary-new.json
```

`freeze` запускать только для нового эксперимента: существующий manifest
не перезаписывается. В этом эксперименте повторно используется готовая выборка.
`orcid` при повторе не отправляет запросы для уже записанных результатов;
`--retry-transport` явно повторяет только ConnectError и сохраняет предыдущие
результаты. 403/429 создаёт сохраняемую остановку источника, повторный запуск
её не снимает. После исчерпания 150 попыток запросы прекращаются.
Дата/URL/статус допуска ORCID находятся в `orcid-rules.json` вне git; перед
новым сбором надо заново проверить действующие правила. Mailto задаётся
из существующей настройки, credentials в worktree не копируются.
