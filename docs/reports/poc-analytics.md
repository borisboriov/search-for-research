## Архитектура и хранение

Путь запроса: браузер → Caddy → Next route handler → внутренний FastAPI.
PostgreSQL 17.11-bookworm находится в том же Compose на текущем VPS;
порты API/БД наружу не опубликованы. Каталог, ETL SQLite, файловый индекс,
эмбеддинги и ранжирование остаются в прежнем виде. SQLAlchemy 2/Psycopg 3
используются только для аналитики; Alembic имеет отдельную цепочку и
`analytics_alembic_version`. Перенос БД на отдельный сервер требует изменения DSN.

| Таблица | Содержание и связь |
|---|---|
| `analytics_searches` | search_id PK; request_id unique; visit_id; received/completed/persisted timestamptz; статус/исход; серверный JSONB результата, confidence, параметры/пороги, упорядоченные ID/score/rank/grade, версии приложения/индекса/модели, cache hit, задержки |
| `analytics_context` | FK search_id; полный raw_query; отдельно строка поиска после strip; закрытые IP/URL/Referer/допустимые заголовки |
| `analytics_events` | event_id PK; unique visit_id/client_seq; search_id/request_id; received/persisted/client_at; имя/страница/data/версия/класс трафика |
| `analytics_event_context` | FK event_id; закрытый HTTP-контекст; ingest_request_id фактического приёмника |

Индексы поддерживают период, визит/sequence и попытку/имя события.
Search.request_id идентифицирует запрос поиска, Event.request_id связывает с ним
событие; EventContext.ingest_request_id фиксирует отдельный HTTP приёмника.
События могут прийти раньше поискового факта, поэтому их search_id не имеет
обязательного FK, мешающего независимой доставке. Первый устойчиво принятый факт
сохраняется при конфликте ID; повтор не увеличивает воронку.

Миграции `analytics_0001` создают таблицы, `0002` добавляет unique visit/sequence,
`0003` — ingest_request_id. Новая и существующая БД обновляются оператором.
Свежий том с SQL initializer проверен настоящим PostgreSQL 17.11: обе роли
минимальны, reader read-only, повтор сохраняет прежние пароли, restart сохраняет роли.
Runtime получает INSERT и SELECT только PK для RETURNING; нет UPDATE/DELETE/DDL
или чтения полного контекста. Reader отдельно получает SELECT и read-only по
умолчанию. Инициализация ролей — SQL через psql, повтор сохраняет существующие
пароли и отвергает неожиданно повышенные права.

Все серверы/соединения используют UTC, типы времени — timestamptz. Период отчёта
`[start,end)` определяется received_at, а не неверными часами браузера.
Клиентский client_at сохраняется для диагностики; client_seq определяет порядок
внутри визита независимо от задержки/перестановки доставки. Длительности сервера
и браузера измеряются монотонно и показываются отдельно.

## Контракт событий v1 и интерфейс

Строгие контракты: [API](../../apps/api/src/sfr_api/analytics/contracts.py),
[браузер](../../apps/web/lib/analytics-contract.ts). Неизвестные поля запрещены;
query и произвольный текст не передаются по каждому событию.

| События | Наблюдение |
|---|---|
| `visit_started` | Первый клиентский наблюдаемый визит с viewport/release |
| `search_attempt`, `search_validation_failed` | Отдельная попытка или отказ валидации; текст хранит только сервер поиска |
| `results_shown`, `weak_shown`, `empty_shown`, `search_error` | Первый видимый UI после ответа; техническая ошибка отделена от confidence none |
| `profile_opened`, `profile_direct` | Явный переход из выдачи с позицией или отдельный прямой вход |
| `search_reformulated`, `topic_followed` | Связь previous_search_id с новой попыткой; повтор имеет source=repeat |
| `filters_applied`, `sort_applied` | Фактическое применение; закрытие панели ничего не подтверждает |
| `work_selected`, `work_confirmed` | Выбор работы и подтверждение включения |
| `letter_copy_success/failed`, `address_copy_success/failed` | Результат Clipboard API; нажатие не считается успехом |

visit_id — UUID одной живой вкладки в sessionStorage. Reload сохраняет его;
новая вкладка получает новый, клонированные вкладки разделяет BroadcastChannel.
Без этого API клонированные вкладки могут разделить ID — известное ограничение.
Cookie, постоянного межвизитного ID и авторизации нет. Будущие аккаунты могут
связываться с отдельными визитами, не меняя семантику нынешнего ID.

Показ отправляется после client commit и видимого document. SSR/ISR/prefetch
и повторный render не являются человеческими просмотрами. Атрибуция профиля
сохраняется после явного клика, расходуется при открытии, истекает через 30 секунд;
reload открытого профиля сохраняет исходную связь, последующий прямой вход — нет.

Клиент различает HTTP 422/429/502/503/504, таймаут и сеть. Сервер хранит свои
результаты/ошибки независимо от клиента. Текст запроса сохраняется до strip;
нормализованный вариант отдельный. Старый успешный stdout JSONL /match остаётся
совместимым; постоянный `analytics-export --format match-jsonl` воспроизводит
его прежние поля и смысл, включая strip query.

## Доставка и ограничения надёжности

Каждая порция сначала записывается в fsynced-файл 0600 в постоянном томе
analytics-journal; каталоги 0700. Поиск ожидает append максимум 250 мс,
приёмник 500 мс. Ошибка аналитики сохраняет ответ поиска; успешный ACK событий
выдаётся только после устойчивого файла. В случае таймаута фоновая запись может
завершиться позднее: повторяет те же ID, ложного ACK нет.

Replay каждые 5 секунд, одной PG-транзакцией с ON CONFLICT DO NOTHING; отдельные
append/replay locks исключают зависимость append от подключения к БД. PG pool=2,
overflow=0, ожидание/connect/statement ограничены одной секундой. После commit
сохраняется fsynced gzip-архив, затем удаляется pending; рестарт между этапами
безопасно повторяет транзакцию. Некорректные JSON/формы/схемы и старые tmp
сохраняются в quarantine, не блокируя остальные записи.

Pending ограничен 512 МиБ/10 000 файлов, резерв диска 64 МиБ. Архивы не имеют
автоматического удаления и продолжают занимать место. Caddy roll_disabled и
операторская rotate сохраняют закрытый access-лог перед сжатием; это короткий
перезапуск только выбранного proxy. Оператор контролирует очередь/возраст,
quarantine, последнюю запись/догрузку, категории ошибок и место; при нехватке —
внешняя выгрузка с SHA-256 и расширение диска, без автоматической потери истории.

Клиентская очередь sessionStorage ограничена 100 событиями, отправляет порции
до 10/16 КиБ, сохраняет IDs до ACK, повторяет с backoff до 60 секунд. Next
проверяет схему/streaming body и делает один ограниченный повтор. Закрытие
вкладки, недоступное sessionStorage, потеря сети и переполнение могут оставить
неполную последовательность. Абсолютная полнота не обещается.

## Границы данных и доступ

Запросы с именами/контактами не редактируются автоматически: это **чувствительные
исследовательские данные**, не обезличенные логи. Закрытый контекст допускает
raw IP, URL/Referer до 2048 символов без credentials/query/fragment, User-Agent и
Accept-Language до 512 символов. Authorization, Cookie, Set-Cookie,
X-Revalidate-Secret и любые остальные заголовки не собираются. Caddy удаляет
все request/response headers и URL query из access/runtime request logs.
Разрешённые заголовки — диагностическая allowlist, не перечень секретов по именам.
Forwarded-данные принимаются только по цепочке Caddy → Next с закреплённым IP →
API; Caddy перезаписывает входной клиентский IP, произвольный XFF не доверен.

Сырые данные/backup/export вне git и web static, 0700/0600. HTML содержит
агрегаты, строки экранируются; полные запросы экспортируются отдельной закрытой
командой. Нет сбора черновика письма, посимвольного ввода и новых форм контактов.
Состав/доступ/хранение переданы в [#39](https://github.com/borisboriov/search-for-research/issues/39#issuecomment-5960857584),
без заявления юридической готовности. [PILOT_TEST_GUIDE](../PILOT_TEST_GUIDE.md)
исправляет неверную формулировку о персональных данных первого пилота.
Исходный архив #165 не изменялся и не публиковался; его неполнота/секретные
заголовки — ограничение старого источника, не импортированные новые события.

## Отчёты и эксплуатация

Команды и rollout — [deploy/README](../../deploy/README.md#аналитика-poc-postgresql-журнал-и-доступ).
Make-цели: analytics-migrate/check/replay/report/export/backup/restore-check/pull/
rotate/test-postgres/test-caddy. HTTP-ручек выгрузки/отчёта нет.

Отчёт требует явные start/end/timezone (Europe/Moscow поддержан), выдаёт локальные
HTML, summary.json и funnel/attempts/dimensions.csv. Последовательная воронка
visit → attempt → display → profile → letter_copy проверяет одну search_id/
visit_id и порядок client_seq; для завершения нужен тот же открытый author_id.
Числа и знаменатели показаны отдельно для попыток и визитов. IP/Referer не
склеивают поиски. none/weak/ok — серверный факт, технические ошибки отдельно.
Технические UA и предполагаемые боты — отдельные группы; это эвристика, не
доказательство личности. Прямые профили, повторы, release/index/device,
серверная и клиентская latency, пробелы/clock anomalies/replay lag видимы.

Период ограничивает принятые сервером события: визит до начала периода не
становится новой последовательной воронкой внутри него. Поздняя доставка требует
пересчёта. Отсутствие следующего события означает отсутствие наблюдения, а
копирование письма — поведение, не отправку/ответ/качество подбора.

Backup — transaction-consistent pg_dump custom, не копия живого PGDATA.
Проверочное восстановление создаёт новую sfr_restore_* БД, сохраняет её и
сверяет число записей/row fingerprints/версию схемы на неподвижном наборе.
Pull потоково читает dump/journal/access archives на Mac; manifest SHA-256.
Это согласованная БД, но активные журналы могут дописываться — не общий snapshot
всех файлов. Backup на том же VPS не заменяет внешнюю копию. Cron-конфигурация
подготовлена, на production не установлена.

## Ревью, DoD и передача

Независимое ревью и его актуальные base/head фиксируются отдельным комментарием
в PR по процедуре review-iteration. После исправлений требуется актуальный CI
checks/web/audit и handoff-check; старый зелёный запуск не является подтверждением.

Порядок после продуктовой приёмки: отдельное разрешение merge/выкладки → внешняя
копия и проверочное восстановление → provisioning ролей/миграции → приложение →
analytics-check и smoke UI → ресурсные наблюдения. Откат приложения сохраняет
analytics-db и analytics-journal, down -v и downgrade миграций не выполняются.
Результат передаётся для sfr-verify-session, затем sfr-close-round.

Предложения продуктовому потоку: после приёмки отразить фактическую доступность
аналитики и чувствительный состав данных; юридические документы вести по #39.
Паспорт/финансы/Drive не изменялись, новых заявлений качества нет.

### Исправления независимого ревью

Исходный проход sfr-reviewer подтвердил две Medium-находки, опубликованные
[комментарием PR](https://github.com/borisboriov/search-for-research/pull/179#issuecomment-5961696381).
Исправлены check exit policy и наблюдаемые sequence gaps; добавлены проверки
legacy/current/queue/quarantine/history/lowdisk, late-fill/duplicates/period limits.

по 16 HTTP-запросов накопили 16 → 32 → 48 незавершённых append/потоков, хотя

стабильны на 2; потоки 9 → 11 → 11, max HTTP 509,700 мс, поиск 200/события 503.
