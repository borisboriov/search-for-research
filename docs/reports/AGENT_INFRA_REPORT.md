## §2 Разрешения и условия применения

Разрешены проверки Python/web, `uv sync --locked`, `npm ci`, создание своей
ветки, add/commit и `git push -u origin <ветка>`, issues/PR этого репозитория,
аудит и синхронизация доски. Чтение файлов и состояния git обычно работает
внутри песочницы и отдельного allow-правила не требует.

Файл правил находится в слое этого проекта. Он не установлен в глобальный
`~/.codex/rules/`. Allow-правила являются префиксами команд; ограничения
опасных push/merge дополнительно проверяет hook. Инструкции требуют работать
только над порученной задачей и своей веткой. Произвольные `bash`/`python`,
весь `git` или все цели `make` не разрешались общей записью.

Определения hooks содержат абсолютный путь этого Mac. Они не изменены, чтобы
сохранить существующее доверие; перенос на другой путь требует адаптации и
проверки через `/hooks`. Доверие проекту уже присутствует в пользовательском
config; credentials и содержимое глобальной конфигурации в репозиторий не копировались.

В обеих реализациях guard закрыты найденные обходы: составные короткие
force/delete-флаги, сокращённые неизвестные длинные опции, wildcard/matching
refspec, main/master при remote через `--repo`. В разрешённых make-вызовах
проверяются дополнительные цели/опции и `AUDIT_ARGS`; в SFR gh-вызовах —
повторный выбор repo. При ошибке разбора или чрезмерной вложенности guard
отказывает. Тесты не исполняют проверяемые push/deploy-команды.

Native `sfr-judge` не фиксирует Fable: роль наследует модель родителя, требует
явно определить фактическую модель до разметки и описать её в отчёте. Backend
Fable этим тредом не настроен; идентичность и сравнимость нового судейства с
прежним не заявляются. Судейские файлы и метрики не менялись.

Проверки политики выполнялись `codex execpolicy check`, команды из тестовых
векторов не исполнялись. Запуск реальной сессии после перезапуска с новыми
skills/правилами ещё не проверен; существующие роли доступны в текущем окружении.
