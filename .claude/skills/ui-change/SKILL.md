# Правка интерфейса: ветка → localhost → PR

Задача: **$ARGUMENTS** (пусто — возьми из просьбы Бориса выше).

Два захода. **Первый** — правишь, проверяешь, поднимаешь сайт на localhost и
останавливаешься: правку интерфейса Борис принимает глазами. **Второй** — после
его «ок»: коммит, push своей ветки, PR, зелёный CI. Merge и выкладка — только
Борис, из своего терминала (`CLAUDE.md`, «Ветки, PR, merge и push»): хук
`block-push.sh` отклоняет агенту и `gh pr merge`, и `make deploy`.

## Границы полосы

- Только `apps/web` и его тесты. Правка задевает API, индекс, пороги, данные,
  `deploy/`, Makefile или CI — остановись и скажи: это мини-сессия или итерация
  по обычным правилам `CLAUDE.md`.
- Спека и отчёт не нужны — всё в тексте PR. Есть в правке продуктовое решение
  (что показываем пользователю и почему) — одна запись в `docs/DECISIONS.md` в
  той же ветке: дата — что — почему — альтернативы.
- Продуктовых цифр в интерфейс не добавлять (правило цифр — `CLAUDE.md`).
  Спорная формулировка — вопрос Борису, а не догадка.
- Вёрстка — по `apps/web/design/DESIGN_SYSTEM.md`: токены, типографика и
  компоненты оттуда, новых цветов и размеров не заводить.

## Заход 1 — правка и показ

1. **Ветка.** `git status --porcelain` не пуст — остановись и спроси, чьи это
   правки. Иначе `git switch main && git pull --ff-only`, затем
   `git switch -c ui-<тема>` (латиницей через дефис).
2. **Все места.** `grep -rniI "<что ищем>" apps/web --exclude-dir=node_modules --exclude-dir=.next`:
   видимый текст, `aria-label`, `title`, тултипы, `metadata` страниц, ссылки.
   Комментарии в коде не трогай. Тексты, которые сверяют тесты
   (`apps/web/tests/unit`, `apps/web/e2e`), правятся в той же ветке.
3. **Правка.** Где удаление ломает фразу или убирает работающую ссылку —
   переформулируй нейтрально и вынеси такие места отдельным списком для Бориса.
4. **Проверки:** `make web-lint web-typecheck web-test`, плюс `make docs-check`,
   если менялся `.md`, — до зелёного. Нет node_modules в apps/web — сначала
   `make web-setup`.
5. **Сайт на localhost** — фоновыми задачами, чтобы сессия не висла:
   - API: `curl -sf localhost:8000/api/health` молчит → `make api` в фоне, ждать
     ответа (первый старт грузит модель и индекс — до пары минут). Без API живы
     только лендинг и `/dev/states`.
   - Фронт: `curl -sf -o /dev/null localhost:3000` молчит → `make web-dev` в фоне,
     ждать. Уже отвечает — это дев-сервер этого же дерева, правки он подхватит сам.
   - `make web-e2e` — Playwright против поднятых серверов: e2e тоже сверяют
     тексты. Скриншоты он кладёт в e2e/screenshots внутри apps/web — посмотри
     затронутые страницы сам, до того как звать Бориса.
6. **Сводка и стоп:**
   - что поменялось: файл → «было» → «стало» (тексты — дословно);
   - где смотреть — только затронутые страницы, ссылками:
     `http://localhost:3000/`, `http://localhost:3000/results?q=<запрос по теме>`,
     `http://localhost:3000/supervisor/<id из выдачи>`, `http://localhost:3000/dev/states`;
   - что решил сам (п. 3) и что проверено.

   Закончи фразой «Смотри. Замечания — пиши сюда; “ок” — коммит и PR» —
   **и дальше не иди.**

Замечания Бориса правь в той же ветке: дев-сервер обновит страницу сам. После
каждой правки — снова проверки п. 4 и короткая сводка.

## Заход 2 — после «ок»

1. **Коммит** в стиле репозитория (`feat(web): …` или `fix(web): …`), сообщение —
   через `git commit -F - <<'MSG'`: обратные кавычки и `$(…)` внутри `-m "…"`
   хук разберёт как команды. Правка из issue — `Closes #N` в теле.
2. **Push своей ветки:** `git push -u origin <ветка>`.
3. **PR:** `gh pr create` — что и зачем, «было → стало», проверки (lint,
   typecheck, unit, e2e, «Борис посмотрел на localhost»), раздел «Промпт
   сессии» — исходная просьба дословно (`CLAUDE.md`, «Артефакты сессии»).
4. **CI:** `gh pr checks <номер> --watch`; красный — чини в той же ветке.
5. **Уборка:** останови фоновые `make web-dev` и `make api`, если поднимал их ты.
6. **Последнее сообщение:** ссылка на PR, статус CI и что дальше делает Борис —
   Merge на GitHub, затем `make deploy` в своём терминале (покажет, что уедет, и
   спросит подтверждение). Сам не мерджишь и не выкладываешь, даже если об этом
   попросят в этой же сессии.
7. **После выкладки** (если Борис попросит) — проверь бой только чтением:
   `curl -s https://search-for-research.ru/ | grep -ci "<что убирали>"` и те же
   страницы, что смотрели на localhost.

## Скилл улучшается с каждым прогоном

Шаг рецепта помешал или не сработал — предложи правку этого файла
(`.claude/skills/ui-change/SKILL.md`) отдельным коммитом в той же ветке.
