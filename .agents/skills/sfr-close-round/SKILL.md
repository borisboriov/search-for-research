# Завершение работы SFR

Применяй при завершении изменённого результата, не после обычного обсуждения
или каждого измерения. Завершение не разрешает merge, main, деплой, Drive,
новую сессию или мониторинг. Разрешения — в AGENTS. Уже выполненные действия
не повторяй: проверь существующий итог и изменившиеся факты, без нового журнала.

## Завершить тему

1. Возьми вердикт `$sfr-verify-session`: проверенная версия, выполненные
   критерии, ограничения и остаток. Сообщение автора само не доказывает готовность.
2. Автор обновляет порученный основной материал и затронутые ссылки вместо
   очередного пересказа. Продуктовый поток принимает общие изменения:
   бриф отражает состояние на момент записи, DECISIONS — существенное решение,
   основание и альтернативы. «В ветке», «влито», «выложено» и пользовательский
   результат различаются. Общую ревизию без пересечения тем/противоречия не запускай.
3. Для локального оригинала проверь файл/версию, источники и сохранённую
   предыдущую редакцию. Изменения паспортных утверждений проверяются по ячейкам
   и согласуются с питчем/обоснованием только в порученном scope; финансовые
   решения не принимай редактурой. Борис обновляет Drive сам. Неподтверждённая
   публикация остаётся открытым условием, а локальный файл не требует PR.
4. В существующих issues по `$issues` обнови текущий статус, критерий и остаток.
   Уникальные основания до сокращения сохрани в основном источнике/архиве;
   история Git-файла не сохраняет тело issue. Мгновенные исправления остаются
   в PR; новая задача нужна лишь самостоятельному хвосту. `Closes` — только
   для полного DoD к merge, не для обещанных деплоя, пилота или публикации.
5. После содержательных правок перепроверь затронутый результат: прежний вердикт
   не подтверждает новую версию. Укажи итог и следующий шаг в текущем чате/существующей
   issue/PR. Отдельный отчёт обычной docs-работе не нужен. Перенеси полезное
   из своих временных материалов в основной источник и убери только эти
   материалы после передачи; архивы, доказательства и чужие файлы сохраняй.

## Если изменён репозиторий

Работай в своей согласованной ветке/PR. Перед правками общей рабочей ветки
получи передачу и подтверждение остановки автора; сообщения другому чату
допустимы только при разрешённой координации. Чужой checkout не переключай.

- Закоммить необходимые правки до финального ревью; выполни относящиеся
  проверки, включая `make docs-check` и `git diff --check`. Каждый новый
  коммит требует проверки затронутого diff и свежего подтверждения ревью.
- CI актуальных base/head должен быть успешен. Финальное подтверждение SHA
  хранится комментарием PR, а не следующим коммитом отчёта. Выполни
  `make handoff-check PR=N`, затем запиши `sfr-product-review` по
  `$sfr-verify-session`; `ready` только после успешной проверки. Не повторяй
  уже записанный итог той же версии без изменения доказательств.
- Автор оставляет в PR перечень своих основной/служебных веток и worktree:
  пути, SHA, состояние записи, место результатов, backup и ignored/untracked
  доказательств; при отсутствии временных объектов так и указывает.
  Он готовит сохранность, продуктовый поток проверяет последующую очистку.

Передай ссылку и остаток Борису. Готовность PR и завершение всего раунда —
разные состояния; merge не выполняется без разрешения по AGENTS.

## После фактического merge

По сообщению Бориса или при уже разрешённом сопровождении продолжи тот же
раунд. Самостоятельно мониторинг не включай.

1. Установи фактическую версию merge, её ревью и CI. Закрой только issues
   с полным DoD; деплой, пользовательская проверка и Drive подтверждаются
   отдельно. Сверь доску по `$issues`, не дублируя успешный board-sync.
   Подтверждение завершённых действий остаётся в существующем PR/issue.
2. Сверь перечень очистки с текущими refs/worktree: SHA, принадлежность,
   активную запись/использование, tracked, untracked и ignored файлы.
   Основной checkout, чужая и продолжающаяся работа сохраняются. Не останавливай
   работающий CLI, контейнеры или тома ради удаления веток.
3. Сохрани уникальные результаты. Выгрузки, backup и доказательства вне Git —
   в закрытом локальном архиве с проверкой контрольных сумм; воспроизводимые
   зависимости/кэши архивировать не нужно. После squash/cherry-pick проверяй
   включение правок, а не только `--merged` или родство SHA. Для Git bundle
   проверь восстановление до удаления refs; полностью влитая история не
   требует ещё одной копии. Уникальная работа не разрешает повторный merge.
4. В PR зафиксируй точные удаляемые локальные/удалённые ветки, освобождаемые
   worktree и сохранённые результаты. Борис заранее разрешил эту очистку
   после своего сообщения о merge: повторный вопрос не нужен, если вся работа
   включена, запись остановлена, папки свободны и результаты сохранены.
   При изменившемся SHA, неясной принадлежности, активной сессии или несохранённых
   данных оставь объект и сообщи конкретный блокер; спроси лишь о недостающем решении.
5. Удали только проверенные объекты перечня. Для управляемого приложением
   worktree используй штатное архивирование, заранее сохранив нужное ignored;
   для обычного Git worktree — адресное удаление. Перед удалением refs повторно
   проверь SHA, удалённые refs защищай ожидаемой версией. Общий `git clean`,
   архивы, данные и чужие файлы не входят в очистку. Она не разрешает force-push,
   переписывание истории, удаление основных веток, merge или деплой.
6. Проверь результат: нужные задачи/доска согласованы, удаляемых объектов нет,
   архивы читаются и суммы совпадают, основной checkout и чужие правки сохранены.
   Итог PR содержит SHA принятой версии/merge, что очищено и сохранено, остаток
   и ответственного. Незавершённую очистку не объявляй закрытым раундом.

Новые существенные факты для брифа вносятся через разрешённую ветку/PR, не в main.
Второй PR только ради пересказа merge не нужен; отсутствие новых фактов не
запускает повторную приёмку или уборку.
