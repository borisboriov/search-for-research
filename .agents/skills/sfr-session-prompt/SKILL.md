# Постановка и сопровождение технической сессии SFR

Выбери режим по поручению: **подготовить** — выдать промпт и проверенную
команду для Бориса, без запуска и мониторинга; **сопровождать согласованный
цикл** — работать с точно установленной существующей сессией/PR до проверенного
результата, блокера или согласованного лимита. CLI в терминале PyCharm Борис
запускает сам. Существующий чат приложения можно продолжить штатным инструментом
после разрешения Бориса передавать ему задания; это разрешение сохраняется
в пределах согласованного цикла. Новый пользовательский чат создавай только
по прямой просьбе. Не управляй терминалом через Computer Use. Постоянный адрес постановки до PR —
связанная issue, после — раздел «Промпт сессии» в PR. Отдельный файл промпта
и отчёт подготовки не нужны.
В режиме подготовки не создавай issue/PR и не меняй их без отдельного
поручения сохранить постановку; достаточно результата в текущем чате.

Пути ниже относительны корню рабочего репозитория/worktree, даже когда
продуктовый чат запущен из папки Desktop. Не ищи repo-skills в папке документов.

## Собрать контекст

Прочитай `AGENTS.md`, живой экран `docs/product/brief.md`, связанные issues
с комментариями, спеку только при работе в её скоупе и относящиеся к задаче решения
`docs/DECISIONS.md`. DECISIONS хранит решения и основания, не второе состояние.
Отчёты и измерения читай по теме; команды проверяй по Makefile и README.
Не переносить в промпт всю историю или цифры из памяти.

Для полной итерации требования живут в спеке и связанных issues. Мини-сессии
достаточно конкретной постановки и критериев приёмки в issue/PR, без новой
спеки. Обычное продуктовое обсуждение не требует issue. В уже разрешённом
техническом цикле без PR/issue найди или создай задачу по `$issues` для передачи
между сессиями; при подготовке лишь укажи этот шаг в промпте.
Само название будущей итерации не разрешает начать её.

## Что включить в промпт

- Цель, ожидаемый пользовательский результат, критерии готовности, связанные
  issues и ограничения. `Closes #N` допустим только для полного DoD задачи;
  если нужны выкладка, пользовательская проверка или Drive, пока обычная связь.
- Короткий порядок чтения: постановка, нужные разделы документов и доказательства.
- Своя ветка от актуальной согласованной базы; точные границы файлов и данных.
  Продуктовые документы и паспорт меняются по прямому поручению Бориса или
  передаче этой работы продуктовым потоком, а не попутно с технической работой;
  не меняет инструменты измерения в том же прогоне, где ими оценивает результат.
- Этапы работы и подходящие проверки из реального Makefile/README. Для
  измерений — корпус, набор, рубрика и судья. Прежние оценки Fable и новые
  `gpt-6-astra/max (sfr-judge)` не смешивать без отдельного сравнения.
- Ранний draft PR после первого содержательного коммита и push своей ветки:
  он даёт адрес работы и запускает CI. Затем независимый `$review-iteration`,
  исправления, проверка затронутого diff и CI актуальной версии PR. Перед
  передачей — `make handoff-check PR=N` (подставить номер): актуальное
  подтверждение `sfr-review` в PR и успешные checks/web/audit обязательны.
- Связь с исходным продуктовым чатом в теле PR:
  `<!-- sfr-product-thread: <фактический UUID продуктового чата> -->`.
  В готовый промпт подставь проверенный текущий ID; мастер не хранит UUID.
  Если ID неизвестен, не выдумывай его и не считай фоновую связь настроенной.
- Результат и ограничения в PR. Техитерация/эксперимент оставляет отчёт с
  измерениями и DoD; обычная правка документов — документ и PR. Существенные
  решения — в DECISIONS; `SESSIONS.md` не дописывать. Предложения паспорта —
  по ячейкам с источником и оговорками, статус — в issue `human` + `docs`.
- Передача продуктовой приёмке по `$sfr-verify-session`, затем подготовка
  документов по `$sfr-close-round`. Автор прекращает запись в общую ветку,
  пока продуктовый поток синхронизирует документы, и явно подтверждает это в PR.
  После новых коммитов снова
  проверяются ревью и CI. Merge и деплой — только по отдельной команде Бориса.
- Перечень для завершения по `$sfr-close-round` в существующем PR: собственные
  основная/служебные ветки и worktree с путями, SHA и состоянием записи;
  расположение сохраняемых результатов, ignored/untracked доказательств,
  выгрузок и backup. Исполнитель готовит сохранность и пакет очистки,
  продуктовый поток завершает очистку после сообщения Бориса о merge без
  повторного разрешения, в границах и после проверок `$sfr-close-round`.
  Готовый PR ещё не закрытый раунд.

## Запуск и передача

Для ручного CLI проверь установленный клиент и справку, подготовь команду
перехода в нужный repo/worktree и промпт для вставки. Для разрешённого продолжения
в приложении проверь ID чата, статус, ветку/PR и текущего писателя, передай
поручение штатным инструментом и проверь подтверждение запуска. Не выдавай
доставку сообщения за выполненную работу. Непроверенные флаги и способы
доставки в CLI не обещай.
CLI самостоятельно выполняет реализацию → независимое ревью → исправления →
повторное ревью → CI. PASS `handoff-check` необходим для заявления о готовности PR к решению
о merge; отдельное разрешение на merge сохраняется. Завершение эксперимента
и достоверность его вывода проверяй отдельно по `$sfr-verify-session`: отрицательный
результат или подтверждённый предел метода могут завершить порученный эксперимент
при явно указанном блокере PR. Не запускай следующий эксперимент автоматически.

До PR фиксируй в исходной issue текущий этап, ветку, чат/сессию (если известен
адрес), блокер и следующий шаг. После появления PR добавь ссылку; дальше
результаты и ревью — в PR, задачи и их статусы — в issues. Не дублируй каждый
шаг в нескольких местах. Follow-up в другой чат допустим после разрешения
Бориса координировать его и только в рамках поручения. Разрешённое сопровождение
цикла покрывает его исправления и follow-up точно установленной существующей
сессии; повторных разрешений не требуй. Если доставки туда нет, исправления
можно поручить субагенту в том же скоупе после передачи ветки без конкурирующей
записи. Новый пользовательский чат для этого не создавай.

Открытый терминал, resume и отправленный промпт не означают мониторинг.
Если Борис разрешил фоновое сопровождение, используй heartbeat текущего
продуктового чата каждые 30 минут, ограниченный конкретным поручением.
Находи PR только по точному маркеру этого чата и связанному скоупу; при нескольких
кандидатах сначала установи нужный PR. До его появления не создавай заменяющую
сессию. Без изменений и действий не присылай повторный статус.
Готовый PR проверь по `$sfr-verify-session`; продуктовые документы синхронизируй
по `$sfr-close-round` после остановки автора. Состояние сопровождения и итог
живут в issue/PR, без отдельного MD или хранилища. Подготовка промпта сама
по себе heartbeat не создаёт; маркер PR не разрешает работу вне поручения.
