# Постановка и сопровождение SFR

**Подготовить** — выдать поручение в текущем чате, без запуска, issue/PR и
мониторинга, если их создание отдельно не поручено. **Сопровождать** — продолжать
точно установленную существующую сессию в разрешённом scope до результата,
блокера или согласованного лимита. Обычное обсуждение этого навыка не требует.
Пути ниже — от корня repo/worktree, в том числе для чата из папки Desktop.

## Поручение

Прочитай AGENTS, бриф, постановку и связанные решения/доказательства по теме.
Не пересказывай всю историю и не восстанавливай цифры по памяти. Для итерации
используй её спеку; для небольшой работы достаточно критериев в существующей
issue/PR. Название будущей итерации не разрешает её начать.

Укажи:

- Результат, критерии приёмки и границы; основной документ/артефакт, его версию,
  автора и короткий маршрут чтения. Различи обсуждение, документы/исследование
  и код/данные/эксперимент по AGENTS. Новая issue нужна для самостоятельной
  задачи/передачи, не для каждого ответа.
- Разрешённые файлы и данные. Изменения продуктовых документов и паспорта —
  только по поручению Бориса или передаче продуктовым потоком. Финансовое
  решение не подменяется редактурой; собственный материал обновляет его автор.
- Проверки из Makefile/README. Для исследования — источники, выводы,
  допущения и неизвестное; для измерения — корпус, набор, рубрика и судья.
  Инструмент измерения не меняют в оцениваемом им прогоне. Старые Fable и
  новые `gpt-6-astra/max (sfr-judge)` без отдельного сравнения не смешиваются.
- Для repo — своя ветка от актуальной согласованной базы, ранний draft PR
  после содержательного коммита и push; независимый `$review-iteration`,
  исправления, проверка нового diff и CI. Передача готового PR требует PASS
  `make handoff-check PR=N`: актуального `sfr-review` и checks/web/audit.
  Локальный оригинал проверяется как конкретная версия, без искусственного PR.
- Результат в основном материале и существующей issue/PR. Отчёт нужен
  техитерации/эксперименту; обычной docs-правке не нужен. Для нового общего
  решения — DECISIONS и принятое состояние, без хроники сессий в брифе.
- Приёмка по `$sfr-verify-session`, завершение по `$sfr-close-round`.
  Автор останавливает запись перед передачей ветки продуктовому потоку;
  новые коммиты требуют свежих ревью и CI. Перечень собственных веток/worktree
  и сохраняемых результатов, включая ignored/untracked, остаётся в PR.
  Разрешения на merge/очистку/деплой — только по AGENTS, готовность их не даёт.

`Closes #N` допустим лишь при полном DoD к merge; незавершённые выкладка,
пользовательская проверка или Drive остаются видимыми задачами. Промпт сессии
сохраняется в issue до PR, затем в разделе PR; отдельный handoff-файл не нужен.

## Запуск и продолжение

CLI в PyCharm запускает Борис: проверь установленный клиент и справку,
дай команду перехода в repo/worktree, запуска и промпт для вставки. Не обещай
непроверенные флаги/resume/доставку в CLI; не управляй терминалом через Computer Use.

Существующий чат можно продолжить штатным инструментом после разрешения
Бориса передавать ему задания. Проверь ID, статус, ветку/PR и текущего писателя;
подтверди запуск, не выдавай доставку за выполнение. Разрешение сохраняется
для исправлений в том же цикле; новое поручение вне scope требует решения.
Новый пользовательский чат — только по прямой просьбе. При недоступной доставке
разрешённую работу можно передать субагенту после прекращения конкурирующей записи.

До PR при смене этапа обновляй в issue этап, ветку, адрес сессии, блокер и
следующий шаг. После PR детали работы и ревью живут там; не дублируй каждый шаг.
Содержательный итог эксперимента и готовность PR проверяются отдельно по
`$sfr-verify-session`: отрицательный результат не требует нового эксперимента,
но не отменяет ревью, CI и handoff.

## Только при разрешённом фоновом сопровождении

Открытый терминал или отправленный промпт не означают мониторинг. По отдельному
поручению используй heartbeat текущего продуктового чата каждые 30 минут,
ограниченный этой работой. Связь в теле PR:
`<!-- sfr-product-thread: <фактический UUID продуктового чата> -->`.
Подставляй проверенный ID, не выдумывай его. При нескольких PR установи нужный;
до его появления не создавай заменяющую сессию или второй монитор.

Без нового состояния или действия не повторяй аудит и уведомления. Готовый
PR проходит verify/close после остановки автора; повторные проверки — по
изменившимся доказательствам и версии. Состояние и итог сохраняются в issue/PR,
без отдельного хранилища. Подготовка поручения и маркер не разрешают фон или
новый scope; отключённое сопровождение самостоятельно не возобновляй.
