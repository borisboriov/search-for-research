name: review-iteration
description: Независимое ревью итерации или мини-сессии Search For Research субагентом sfr-reviewer с отчётом и подтверждёнными находками.
---

Проведи независимое ревью указанной пользователем итерации или мини-сессии
с помощью субагента `sfr-reviewer`. Используй чистый контекст: передай только
название работы, диапазон git-diff и пути к требованиям и отчёту, без переписки
автора и подсказок о предполагаемых дефектах. Сам код не правь.

Нативная роль Codex описана в `.codex/agents/sfr-reviewer.toml`, роль Claude Code —
в `.claude/agents/sfr-reviewer.md`. Если роль недоступна в текущем окружении,
используй отдельного агента с этими инструкциями и явно укажи это в отчёте.

Для итерации передай её спеку и `docs/reports/SFR<N>_REPORT.md`.
Для мини-сессии без спеки передай требования из issue или раздела «Промпт сессии»
в PR, её отчёт и диапазон изменений; отсутствующую спеку не придумывай.
Попроси ревьюера записать единственный временный артефакт:
`docs/reports/REVIEW_<имя>.md`. Разрешён только этот файл; исходники и конфигурацию
ревьюер не меняет, команды использует только для чтения.

Когда отчёт готов, прочитай его. Каждая High/Critical находка должна быть
подтверждена цитатой кода. Выведи короткую сводку: число находок по severity,
самые важные и рекомендуемый следующий шаг. Для каждой подтверждённой находки
сначала проверь дубли, затем заведи issue `from-review` по таксономии `AGENTS.md`.
Не выдавай предположение, которому нужен запуск, за подтверждённый дефект.

Итог запиши разделом «Независимое ревью» в отчёте работы: что проверено,
severity, находки и ссылки на issues, что исправлено. Временный `REVIEW_*.md`
в git не идёт; после переноса результатов удали только созданный этим ревью
временный файл. При изменении issues выполни `make board-sync-dry`, затем
`make board-sync`.
