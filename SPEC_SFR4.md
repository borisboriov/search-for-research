## 0. Фиксы по ревью (первым делом, до деплоя)

Из независимого ревью 05.09 — обязательны все High и Medium, Low — по возможности:
1. `lib/api.ts get()`: 404 → `null`; сеть/5xx → `throw`; страница НР при исключении — 500 через error boundary (не кэшируется), sitemap/лендинг — ловят локально. Кэшировать только успешные ответы; частичный список при ошибке пагинации → `throw`. Тест: с выключенным API `/supervisor/<валидный id>` → 5xx, не 404; после включения — 200 без ожидания часа.
2. Прокси `/api/match`: лимит тела ≤ 4 КБ, `AbortSignal.timeout(15000)`, 422 от API пробрасывать с `detail`. API: `query: Field(min_length=3, max_length=2000)` на уровне схемы.
3. API `match`: ограничить конкурентность инференса (`Semaphore(2)`/`CapacityLimiter`), `uvicorn --limit-concurrency 8`, 503 при переполнении; нагрузочный тест 20 параллельных запросов — латентность и отсутствие OOM в отчёт.
4. `/supervisor/[id]`: валидация формата id (`^A\d{4,12}$`) до fetch.
5. `/results`: `validateQuery` до fetch; 422 показывать как подсказку, не как «сервис недоступен».
6. `NEXT_PUBLIC_SITE_URL`: падать на билде в production без переменной; `poweredByHeader: false`; security-заголовки (nginx или `headers()`); `/dev/states` → `notFound()` в production.
7. Dockerfile API: непривилегированный `USER`, `.dockerignore` (`.env*`, `data/`, `**/tests`, `node_modules`), пин `uv`; CI: `uv sync --locked`.
8. Low-пункты (счётчик вузов, ключи works-list, clipboard `.catch`, текст 422, «Топ-5»/k=10) — сделать, это минуты.
9. **Серая зона порога и словесные грейды (решение Бориса 05.09 по живому прогону).** Запрос «интересно computer science backend engineering» дал top-1 = 0.34 и мусорную выдачу (физики/химики), но предупреждение не сработало: порог 0.27 калибровался на бытовых посторонних запросах (score ≤ 0.21), а академически звучащие посторонние запросы ближе к профилям. Сделать: (а) второй порог `SFR_API_SCORE_WEAK` (по умолчанию 0.36 — между минимумом живых попаданий 0.31 и их средним 0.43; вынести в settings, отдавать в health) → API возвращает `confidence: "none" | "weak" | "ok"` вместо/в дополнение к `below_threshold`; (б) фронт: при `weak` над выдачей баннер «Совпадения слабые — похоже, в базе пока нет специалистов по этой теме. Попробуйте переформулировать или уточнить запрос» (стиль `results-empty`, выдача остаётся); (в) **бейдж на карточках — словесный грейд вместо процента**: «высокое совпадение» ≥ 0.42, «среднее» 0.36–0.42, «слабое» < 0.36 (границы в одном месте, из тех же settings через API); процент оставить в tooltip. Обновить макет-расхождение в отчёте, тесты, `/dev/states`. (г) Записать запрос про backend в `packages/sfr-match/eval/external_queries.jsonl` с `source: "boris"` и пометкой «академически звучащий, ответа в корпусе нет» — первый реальный внешний запрос; прогнать eval с ним и показать, что при новых порогах он попадает в `weak`.

## 1. Компоновка и деплой

- `deploy/docker-compose.yml`: `api` (образ из `apps/api/Dockerfile`, **порт наружу не публикуется** — только сеть compose), `web` (Next standalone, `apps/web/Dockerfile` — написать; multi-stage, non-root), `proxy` (Caddy — автоматический TLS для `DOMAIN`; или nginx + certbot — выбери, обоснуй). Restart policy `unless-stopped`, healthchecks у всех трёх.
- Прокси-правила: `client_max_body_size 16k`, `proxy_read_timeout 30s`, security-заголовки, gzip; `/api/*` внутрь только на `web` (API снаружи недостижим).
- Артефакты доставляются, не собираются на сервере: `data/indexes_sfr2/`, `data/exports/cards.jsonl`, веса FRIDA (том с кэшем HF; первый старт может скачать — допустимо, но зафиксируй время). `deploy/sync-artifacts.sh` — rsync с чексуммами.
- `deploy/README.md`: пошаговая процедура с нуля (пакеты, docker, пользователь, ключи, env, `docker compose up -d`, проверки) и процедура обновления (`git pull` + сборка образов + пост-деплойная ревалидация `/` и `/sitemap.xml`). Сборка `web` — с `NEXT_PUBLIC_SITE_URL=https://DOMAIN` и доступным API (или с последующей ревалидацией — что выбрал, то и в README).
- Локальная репетиция обязательна: тот же compose поднимается на машине разработчика (`make deploy-local`), проходят e2e против него.
- Если `VPS_HOST` задан: развернуть; DNS A-запись — на Борисе (проверь `dig`, если не указывает — остановись и запиши в TODO_BORIS); TLS выпущен; `https://DOMAIN` отдаёт лендинг.

## 2. Защита и наблюдаемость API (до публичной ссылки — обязательны)

- Rate limiting на прокси/Caddy: `/api/match` — например 10 запросов/мин с IP + burst; каталожные GET и страницы — щадяще; **поисковые боты по User-Agent не режутся** (Googlebot, YandexBot) — проверка в отчёте.
- Логи запросов `/match`: timestamp, хеш IP, длина запроса, текст запроса, top-1 score, `below_threshold`, латентность, `model`/`index_version` — JSON-строки в файл/stdout, ротация. Это материал следующей калибровки порога — формат согласуй с `packages/sfr-match/eval`.
- Кэш ответов `/match` по нормализованному запросу (LRU в памяти, TTL ≥ 1 ч) — дешёвый способ поднять потолок FRIDA; в health — hit-rate.
- Uptime: простой чек `/api/health` и `https://DOMAIN` (cron + curl на самом сервере с записью в лог достаточно; внешний сервис — на Борисе).
