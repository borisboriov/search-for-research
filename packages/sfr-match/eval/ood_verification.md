# Проверка посторонних запросов (SFR-2 §4)

Урок SFR-1: два из четырёх «заведомо посторонних» запросов оказались не посторонними —
история России нашла Горбачёва, выпечка хлеба нашла работу про экструдированные
зерновые хлебцы. Причина была не в модели, а в том, что автор набора плохо знал корпус.
Поэтому в SFR-2 каждый кандидат проверяется до включения в набор.

## Процедура

Кандидат остаётся в наборе, только если выполнены **оба** условия:

1. **Прямая проверка.** Запрос прогоняется по корпусу (FRIDA, `frida_clean`, 535 профилей);
   в его топ-5 нет профиля, которого разумно предложить студенту как НР по теме запроса
   (оценка ≥1 по рубрике SFR-1).
2. **Контрольный перефраз.** Тема запроса переписывается как исследовательский вопрос
   («уход за аквариумом» → «гидробиология и содержание аквариумных рыб») и прогоняется
   отдельно. Если перефраз находит специалиста, для которого исходный запрос —
   узнаваемый частный случай его области, кандидат **отклоняется**.

Второй шаг и есть защита от истории с хлебцами: прямой поиск по бытовой формулировке
часто возвращает шум с низким score, и по нему легко решить, что в корпусе никого нет,
хотя специалист там есть — просто бытовая лексика до него не достаёт.

## Оговорки

- Граница «частный случай области» проведена человеко-подобным суждением одного судьи
  (LLM), а не консенсусом. Спорные места названы прямо: `o10` (вязание против теории
  узлов), `o17` (коляска против психологии развития), `o20` (пятно против ПАВ).
  При сомнении кандидат **отклонялся** — набор из 17 честнее набора из 24 с натяжками.
- Набор состоит из бытовых и потребительских запросов. Это не полный портрет
  «постороннего»: студент скорее спросит про область, которой в корпусе просто нет
  (например, античная филология), чем про починку стиральной машины. Такие запросы
  появятся только с внешним тест-сетом (`external_queries.jsonl`).
- Проверка сделана на корпусе двух вузов. При добавлении третьего часть подтверждённых
  запросов может перестать быть посторонней — набор придётся перепроверять.

## SFR-5, ревью: четыре запроса golden set с устаревшей меткой

Оговорка последнего раздела («при добавлении третьего вуза часть подтверждённых
запросов может перестать быть посторонней») сработала не только на этом файле.
Метку `out-of-domain` несли ещё и **четыре запроса самого golden set** —
`q27`–`q30`, написанные в SFR-1 как «проверка поведения, когда хорошего ответа
нет». В калибровку они не входили: она берёт из golden set только `in-domain` и
`edge`, посторонние — из `ood_queries.jsonl`. Поэтому их устаревание никто не
заметил, а отчёт SFR-5 получил из-за них ложный вывод «распределения разошлись
начисто».
