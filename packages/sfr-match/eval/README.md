# eval/ — наборы запросов и судейство

Файлы здесь версионируются в git: это актив проекта, а не результат сборки.

| Файл | Что это | Кто заполняет |
|---|---|---|
| `queries.jsonl` | golden set SFR-1, 30 запросов | агент (заморожен) |
| `ood_queries.jsonl` | заведомо посторонние запросы для калибровки порога | агент |
| `external_queries.jsonl` | запросы **реальных студентов** | люди — Борис и Света |
| `judgments.jsonl` | оценки пар (запрос, НР): 2 / 1 / 0 | агент (LLM), выборочно проверено человеком |
| `judgments_for_review*.md` | случайная выборка на ручную проверку | агент готовит, человек читает |

Запуск по конкретному набору:

```bash
uv run sfr-match eval --queries external --models frida \
  --index-root data/indexes_sfr2 --runs-dir data/eval/runs_external
```

## Как собрать внешний тест-сет (инструкция для Бориса и Светы)

**Зачем.** Все 30 запросов golden set написал агент, прочитав топ-15 тем корпуса.
Это значит, что набор подогнан под данные: он меряет не продукт, а совпадение
выборки запросов с выборкой профилей. Реальные студенты спрашивают иначе, и доля
«ничего не нашли» у них будет выше. Пока внешнего набора нет, все цифры качества
(Success@5, Success@1) — цифры на своём же поле.

**Главное правило: не показывать корпус.** Ни список тем, ни имена НР, ни примеры
удачных запросов. Иначе получится то же самое смещение, только чужими руками.

**Как спрашивать.** Просьба формулируется одной фразой:

> «Опиши в 1–3 предложениях, чем ты хочешь заниматься в магистратуре/аспирантуре —
> так, как объяснил бы другу. Не подбирай научные термины специально.»

Годится всё: и узкое («безнейтринный двойной бета-распад»), и широкое
(«что-нибудь про ИИ в медицине»), и кривое, и с опечатками. Плохие и размытые
запросы **особенно ценны** — на них проверяется порог «мы никого не нашли».

**Сколько.** 10–15 запросов от разных людей. Лучше 10 честных, чем 15 с двумя
придуманными: выдуманный запрос возвращает нас к той же подгонке.

**Что записать про каждый.** Только текст запроса и курс/направление автора
(без ФИО — набор уходит в git). Если человек описал интерес голосом — записать
дословно, не причёсывая формулировку.

**Куда положить.** В этот файл — `packages/sfr-match/eval/external_queries.jsonl`,
по одному JSON-объекту на строку:

```json
{"id": "e01", "text": "хочу заниматься ИИ в медицине, что-то про снимки", "expect": "in-domain", "source": "student", "comment": "2 курс бакалавриата, ФПМИ"}
```

- `id` — `e01`, `e02`, … (уникальные);
- `expect` — ожидание составителя: `in-domain` (в корпусе двух вузов такой НР,
  вероятно, есть), `out-of-domain` (вероятно, нет), `edge` (короткий, с опечатками,
  на стыке тем). Ошибиться здесь не страшно: это гипотеза, а не оценка;
- `source` — всегда `"student"`;
- `comment` — курс и направление, без имени.

**Что дальше сделает агент.** Прогонит набор через `sfr-match eval --queries external`,
разметит пары по той же рубрике, посчитает Success@1/@5 отдельно по внешнему набору
и сравнит с golden set. Расхождение и будет честной оценкой того, насколько
завышены нынешние цифры.

## Логи /match как источник кандидатов (SFR-4)

Каждый запрос к боевому API пишется JSON-строкой в stdout контейнера
(`docker logs sfr-api | grep '"query"'`) с полями `query` (дословный текст),
`top1_score`, `confidence` (none/weak/ok), `cache_hit`, `took_ms`, `ts`,
`ip_hash`. Формат согласован с этим каталогом: поле `query` переносится в
`external_queries.jsonl` как `text` без изменений, `expect`/`comment`
проставляются руками при разборе (автор лога неизвестен — это гипотеза
разбирающего, как и для запросов от людей). Личных данных в логах нет:
IP — только солёным хешем.

Быстрый отбор кандидатов из лога (упавшие в серую зону и мимо порога —
самые информативные для перекалибровки):

```bash
docker logs sfr-api 2>/dev/null | grep '"query"' \
  | python3 -c "import sys,json
for line in sys.stdin:
    r=json.loads(line)
    if r['confidence'] in ('none','weak') and not r['cache_hit']:
        print(json.dumps({'text': r['query'], 'top1': r['top1_score'],
                          'confidence': r['confidence']}, ensure_ascii=False))"
```
