# Дедупликация SFR-5c — доказательства по 13 парам (#112, #113)

**Что это.** Разбор агента, а не решение: по каждой паре — вердикт `same` / `different` / «без вердикта», уверенность и доказательства. Вердикты попадают в `dedup_decisions.jsonl` только после подтверждения Бориса. Пары — из `dedup_for_review_sfr5c.md`: 11 из раздела «Похоже, один человек, но сигнала не хватило», 1 из «Требуют решения человека» (Усачёв) и находка судьи из #113 (Белогуров).

**Дата:** 2026-09-26. **Данные:**

- `data/sfr5c.db`, только чтение (`mode=ro`): `authors.raw` (имена-варианты, ORCID, аффилиации по годам, темы), `works`. БД не менялась.
- OpenAlex API через `sfr_etl.client` (ключ, polite pool, кэш `data/raw`): **45 запросов** — первая страница `works?filter=author.id:<id>&per-page=200` по каждому из 26 профилей, 6 дополнительных страниц для профилей с >200 работ (Yapaskurt A, Sokoloff A ×2, Sokoloff B, Hossain A, Belogurov B) и 13 запросов `filter=author.id:A,author.id:B` — есть ли у пары совместная работа. К `select` из задания добавлен `doi` — чтобы сверить работы с ORCID. Плюс один анонимный запрос `curl` без клиента — проверка сети. У Jianmin Wu A загружены только 200 из 1 298 работ (для разбора хватило).
- ORCID public API: 16 записей `GET /v3.0/<orcid>` (имя, места работы, работы с DOI). В парах 16 ORCID, а не 9, как было в задании: у 11 пар ORCID есть хотя бы у одного профиля, у пяти — у обоих.

**Как читать сигналы.**

- **Совместная работа.** В OpenAlex у каждого автора в работе одна запись, поэтому работа, которая есть в списках и A, и B, означает, что A и B — **два разных автора этой статьи**. Для склейки это довод против, а не за (так было с Лукинскими). **Ни у одной из 13 пар совместных работ нет** — фильтр по двум id вернул 0 во всех 13 случаях.
- **Раскол профиля** выглядит так: много общих соавторов, те же институты в те же годы, и при этом **ни одной совместной статьи**. Два разных человека из одной лаборатории хотя бы раз были бы соавторами.
- **Доля общих соавторов сама по себе людей не различает.** У Shestakov она 32 %, но это два разных человека: профиль A содержит работы B. У Бескина 19 %, и это один человек. Решает её сочетание с ORCID и составом профиля.
- **Состав профиля.** **Смесь** — в профиле ≥25 % работ другого человека. Это порог `SUSPECT_MIN_SHARE` из `dedup.py`: с такой доли вторая тематическая группа профиля считается «вторым человеком». **Примесь** — меньше 25 %: при склейке эти работы переедут вместе с остальными, и это стоит знать заранее.
- В ответах-списках OpenAlex обрезает `authorships` до 100 на работу (LHCb, STAR, GERDA). У мегаколлабораций поэтому множества соавторов неполные, а сам автор иногда в своей работе не виден.
