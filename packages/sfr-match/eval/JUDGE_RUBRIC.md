# Рубрика судейства пар (запрос, научный руководитель)

*Единственное правило оценки для субагента `sfr-judge` и для любого человека,
который судит пары. Версионируется в git вместе с оценками: оценка без
доступной рубрики невоспроизводима (находка ревью SFR-5c — рубрика жила в
нетрекаемом `.claude/agents/sfr-judge.md`).*

**Текущая редакция — 26.09.2026.** История правил — `git log` этого файла;
редакция, по которой сделана разметка, называется в отчёте итерации.

## Шкала

- **2** — руководитель покрывает *главное содержание* запроса: у него есть работы
  именно об этом (или очень близко), студент с таким запросом пошёл бы к нему.
- **1** — смежно: та же область, но другая задача/объект, или запрос покрыт лишь
  частью профиля; к нему можно обратиться «за наводкой», но тема не его.
- **0** — не по теме: общая только широкая дисциплина или ничего общего.

Источник шкалы — SFR-1 (`docs/SFR1_REPORT.md`); она не менялась ни в одной
итерации, и менять её задним числом нельзя: все прошлые оценки останутся
несравнимыми.

## Как судить

1. Суди **по названиям и фрагментам работ в `profile_text`**, а не по темам
   OpenAlex (`topics`): темы — автоматические ярлыки, они часто шире или сбоку
   от реального содержания (урок сессии 16б). Названия работ — первичный сигнал;
   темы — только подсказка, когда названий мало.
2. Запрос читай как студент: «хочу заниматься X» — ищем людей, у которых X —
   предмет работ, а не упоминание. Кросс-язычность нормальна: русский запрос ↔
   английский профиль.
3. Мегаколлаборации (сотни соавторов: ATLAS, CMS, LHCb, ALICE) — не
   доказательство личной темы; если весь профиль из них, оценивай осторожно
   (обычно 1, а не 2, если запрос узкий).
4. Не зная человека — не додумывай. Оценка только по тексту профиля; если
   профиль пуст или содержит одну работу вне темы — 0.
5. **Прежние оценки не открывай.** Файлы с оценками (`judgments*.jsonl`,
   `judgments_for_review*.md`) для судьи закрыты, даже если путь к ним назван.
   Какие пары оценивать и куда писать, решает вызывающий; судья не проверяет пул
   на пересечение с прежними оценками сам.
6. **Никакого уклона сверх рубрики.** Одинаковые профили при одинаковых запросах
   — одинаковая оценка; сомнение разрешает только шкала (2, если главное
   содержание запроса покрыто работами, иначе 1). Правила вида «сомневаешься —
   ставь строже/мягче» в рубрику не добавляются: они вносят в оценки то, чего
   нет в шкале SFR-1, и делают разметку несравнимой с прошлыми итерациями
   (находка ревью SFR-5c: такой tie-break стоял во втором судействе SFR-5c и
   дал часть расхождения).

## Формат строки

JSON, одна пара — одна строка, UTF-8, `ensure_ascii=False`:

```json
{"query_id": "q07", "author_id": "A5…", "grade": 2, "rationale": "≤ 12 слов: за что оценка", "iteration": "<тег>", "judge": "fable (sfr-judge)"}
```

- `rationale` — коротко и по работам («ML для триггера LHCb, 3 работы»), не
  пересказ темы;
- `iteration` — тег, который назвал вызывающий (`SFR-5c`, `SFR-5c-rejudge-v2`, …);
- `judge` — обязательно: без него нельзя отделить разметку одного прогона от
  другого.

## Что судья сообщает вызывающему

Сколько пар оценено, распределение 2/1/0, куда дописано, и отдельно — пары, где
он колебался между двумя оценками (это кандидаты в выборку на проверку
человеком).

## Границы применимости оценок

- Оценки ставит модель. Человеческого судейства в проекте нет ни в одной
  итерации; выборка на проверку человеком — единственный внешний контроль.
- Success@k сравним между отчётами только на неизменных наборах запросов;
  nDCG между отчётами несравним — судейский пул разный.
- Два прогона одного судьи по одной рубрике расходятся между собой: величина
  расхождения измерена в SFR-5c (§6 `docs/SFR5c_REPORT.md`) и должна называться
  рядом с любой абсолютной цифрой качества.
