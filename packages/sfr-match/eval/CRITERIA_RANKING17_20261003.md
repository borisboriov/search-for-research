## Варианты и бюджет

Baseline — фактический FRIDA DenseBackend. Одна альтернатива: reciprocal rank
fusion (RRF) dense top-50 и BM25 top-50, константа 60, равные веса; BM25 с
score ≤ 0 не участвует. Стабильные ties по author_id. BM25 использует уже
существующую токенизацию/индексированные тексты, без перевода/query expansion.
Основание: BM25 уже есть; лексический сигнал может помочь англицизмам и точным
терминам. Русский запрос и английские работы ограничивают его применимость.
Тяжёлый reranker не добавляется; второй вариант и сетка параметров не нужны.

Бюджет подбора: **0** поисковых прогонов параметров, **1** заранее заданная
альтернатива; отсутствие улучшения допустимо. Три повтора каждого полного пути
на CPU, один warmup, отдельный процесс каждого варианта/повтора для peak RSS;
одинаковые запросы/порядок, варианты чередуются между повторами. Различие
ранжирований между повторами — ошибка детерминированности. Сборка BM25 и cold
startup показываются отдельно. Инструмент и версия harness фиксируются до
сравнения; при его исправлении оба варианта запускаются заново.

## Судейство и метрики

Один независимый sfr-judge: фактические `gpt-6-astra` / `max`, правила из
`.codex/agents/sfr-judge.toml` и неизменная `JUDGE_RUBRIC.md`. Общий пул — union
top-5 baseline/альтернативы по всем группам, unique (query_id, author_id),
сортировка query_id/author_id. Судья видит запрос и снимок профиля, но не
вариант, rank, score, expect, старые оценки. Релевантность — grade 2.
Имена профилей допустимы как публичные данные каталога, персональные сведения
тестеров удалены. Оценки получают предусмотренный `profile_fp` по точному
судимому profile_text; полный `profile_hash` снимка допускается дополнительно.
Старые Fable не используются для вычисления нового baseline.

Success@1/@5: количество успешных / знаменатель и доля для каждой группы;
изменения по каждому запросу, список приобретений/потерь. Неоценённые или
устаревшие пары блокируют расчёт, не считаются нерелевантными. Спорные пары
с альтернативами судьи показываются отдельно и дают min/max Success@k.
nDCG не считаем: общий top-5 пул недостаточен для содержательного corpus recall.
Для OOD: доля ложных допусков baseline cosine ≥0.33 и релевантность top-5;
RRF score не сравнивается с cosine-порогами. Гибрид остаётся локальным
экспериментом без API confidence/грейдов до отдельной калибровки.

Задержки median/p95/max, число ошибок, peak RSS и startup по каждому варианту,
каждому повтору и совокупности; одинаковое число запросов. Mac не доказывает
запас VPS. Никаких выводов о throughput, конкурентности или production SLA.

## Рекомендация, регрессии и DoD

Рекомендовать продолжение гибрида можно только при полном покрытии оценками,
нуле ошибок и детерминированности, без потери Success@1 и Success@5 **у любого**
из golden/edge/пилот/e01 запросов, с приобретением хотя бы одного Success@1
или @5 в golden либо пилоте. На OOD не должно прибавиться grade-2 результатов
в пятёрке; confidence гибрида не заявляется. Совокупный p95 ≤ baseline p95×1.25
+ 50 ms, peak RSS ≤ baseline peak RSS×1.25 + 256 MiB. Эти границы выбраны как
консервативный локальный фильтр дешёвого метода, а не продуктовые SLA.
Если эффект зависит от спорной оценки, продолжение только как гипотеза;
подтверждённым улучшением не считается. При провале любого требования или
отсутствии прироста рекомендация — оставить текущий путь. Малый набор не
доказывает пользу всем студентам и не гарантирует 100% Success@5.

DoD ограниченной сессии: воспроизводимые входы/выходы, свежая Astra разметка
общего пула, сравнение и диагностика с ограничениями, содержательные тесты,
один отчёт в docs/reports, независимое актуальное ревью, обязательные проверки
Makefile и CI, PASS handoff-check, остановка записи и перечень сохранённых
артефактов в PR. Исходный DoD #17 и #7 не объявляется выполненным автоматически;
нет Closes, merge или деплоя. docs/product и паспорт не редактируются.
