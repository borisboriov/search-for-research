# sfr-etl: национальный реестр OpenAlex

`uv run sfr etl national --out data/national-ru --env-file /path/to/existing/.env`
собирает **все** авторские записи по
`last_known_institutions.country_code:ru` и полные российские организации по
`country_code:ru`. Это аффилиация по публикациям, не гражданство. Ограничений
по вузам, works_count, h-index и квотам отбора нет. Кандидаты отмечаются локально
существующей эвристикой `catalog.passes_heuristic`; настройки и календарный год
фиксируются в реестре. Работы, текущая БД, дедупликация и индекс не затрагиваются.

Каталог должен быть отдельным, gitignored (например, внутри `data/`).
Нельзя указывать каталог текущего raw-кэша или базы. Настройки читаются из
существующего env-файла; секреты не копируются в каталог.

## Продолжение и проверка

Повторить **ту же команду** с теми же настройками и каталогом. Проверка локальных
страниц без сети: добавить `--status-only`. `status.json` — измеренный срез на
границе запуска/остановки, не обновляемый каждую секунду статус. Текущий прогресс
смотреть в журнале и в `state`/`pages` отдельного `registry.sqlite3` (read-only).
`verified_local` означает локальную проверку, полноту смотреть отдельно
в `authors.complete` и `institutions.complete`.

Длительный запуск (из worktree с установленными зависимостями):

```bash
mkdir -p data/national-ru
nohup .venv/bin/sfr etl national --out data/national-ru \
  --env-file /path/to/existing/.env > data/national-ru/collector.log 2>&1 &
echo $! > data/national-ru/collector.pid
```

Блокировка предотвращает два процесса на одном реестре. Один общий rate limiter
обслуживает страницы, проверки бюджета и повторы; максимум 10 rps. Другие ETL
процессы с тем же ключом запускать одновременно не следует: бесплатный бюджет
ключа общий. Перед каждой новой страницей проверяется `/rate-limit` и стоимость
list-запроса; предоплаченный баланс не используется намеренно. 429 проверяется по бюджету: исчерпание останавливает сбор, временный rate limit,
5xx и транспортные ошибки имеют backoff с повторной проверкой остатка. При
`waiting_quota` повторить команду после `metadata.budget.resets_at`; фонового
планировщика и покупки кредитов нет. Если другой потребитель ключа одновременно
тратит последний остаток, проверка и страница не являются атомарной операцией API.

## Файлы и доказательства

- `pages/*.json`: полные ответы, входной курсор, время получения; атомарная запись
  с fsync до транзакции реестра. Курсор не продвигается до сохранения всех записей.
- `registry.sqlite3`: `records.raw` — полные последние записи по OpenAlex ID,
  `candidate` — флаг; повторы исходных записей остаются в страницах. `pages` — цепь
  курсоров, SHA-256, API count и число строк; `requests` — попытки, включая retries
  и проверки бюджета, неизвестные исходы явно отмечены NULL.
- `status.json`: уникальные авторы/организации/кандидаты, повторы, диапазон count API,
  состояние бесплатного бюджета, запросы по endpoint, размер файлов и свободный диск.

Проверка полноты: связная цепь от `*` до явного `next_cursor=null` для обоих
endpoint, соответствие checkpoint, отсутствие недостижимых страниц и циклов,
совпадение SHA-256 каждого сохранённого ответа. Не равенство с меняющимся API count.
По умолчанию остановка при свободном месте менее 1 GiB. Повреждённый кэш не
скачивается автоматически повторно: ошибка сохраняет доказательства для разбора.

Сбой **после ответа сервера, но до fsync страницы** может требовать повторного
сетевого запроса: exactly-once между удалённым API и локальным диском невозможно.
Сохранённые страницы никогда не требуют повторной сети. Незавершённые попытки
учитываются отдельно. Полного снимка OpenAlex на одну дату курсорный API не даёт:
изменения фильтра и профилей во время обхода могут менять count и состав выдачи.

## Ссылки на организации вне национального списка

ID из российских last_known_institutions могут отсутствовать в списке
`institutions?country_code:ru` (например, после объединения организаций).
Сборщик получает дополнительные singleton-ответы для таких ID в
`affiliated_institutions/`, с полным JSON при 200, HTTP-статусами и цепью redirect
(только на том же API-хосте). Неполученные сущности 404/410 фиксируются как
ограничение источника. Изменять исходные авторские ID или применять склейки
для этого не требуется. Дополнение кэшируется по исходному ID; национальный
список и его курсорный manifest сохраняются. `status.json` содержит отдельные
supplemental записи и SHA-256. Расход бюджета определяется ценой соответствующей
категории из /rate-limit; бесплатный singleton с ценой 0 допустим при нулевом
остатке list-бюджета. Если получение статуса бюджета недоступно, запрос не уходит.
