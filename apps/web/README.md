# apps/web — фронтенд Search for Research (SFR-3, вид — SFR-6)

Next.js (App Router) + TypeScript + Tailwind v4 + компоненты в стиле shadcn/ui.
Три страницы поверх API `apps/api`: лендинг `/`, выдача `/results?q=…`,
открытая страница НР `/supervisor/[id]` (SSR + ISR, sitemap по каталогу).

Дизайн — источник истины: `design/DESIGN_HANDOFF.md`, `design/DESIGN_SYSTEM.md`
**v2.1** (направление B «Академичная свежесть»; токены §1 лежат в
`app/globals.css`, шрифты Literata + IBM Plex Sans — в `app/layout.tsx`).
Макеты B — в папке документов
(`~/Desktop/Search for Research`/`02_research/2026-09_дизайн_референсы/directions_2026-09-12/`), в репо
их не копируем; `design/mockups/*` — макеты v1, оставлены как история SFR-3 и
источник раскладки для `/supervisor/:id`, которой в B не рисовалось.

## Команды (из корня репозитория)

```bash
make web-setup   # npm ci
make web-dev     # дев-сервер на :3000 (нужен запущенный API: make api)
make web-lint    # eslint
make web-typecheck
make web-test    # юнит-тесты (Vitest)
make web-build   # прод-сборка; живой API не требуется
make web-e2e     # Playwright против живого API; скриншоты в e2e/screenshots/
```

Конфиг: `SFR_API_URL` — адрес API для SSR и прокси (по умолчанию
`http://127.0.0.1:8000`); `NEXT_PUBLIC_SITE_URL` — канонический адрес сайта
(sitemap, OG); `NEXT_PUBLIC_CLAIM_EMAIL` — адрес для «Это вы?» (пока пуст).
Клиентские запросы ходят через route handler `/api/match` — CORS и внутренний
адрес API наружу не выносятся.

Витрина состояний компонентов (skeleton, serendipity, empty, error) — `/dev/states`.


## Продуктовые события текущего PoC

Контракт v1 — `lib/analytics-contract.ts`; Next `/api/events` принимает до 10
событий и 16 КиБ UTF-8 за запрос, проверяет закрытую схему и пересылает во
внутренний API. Только список `accepted` после устойчивой серверной записи
подтверждает доставку. Один повтор в Next ограничен двумя секундами на попытку.
Клиент сохраняет до 100 неподтверждённых событий в sessionStorage, повторяет
с ограниченным интервалом до 60 секунд, сохраняет event_id и client_seq при
повторе/перезагрузке. Переполнение оставляет диагностическое предупреждение
без пользовательского текста и пропуски последовательности; закрытие вкладки,
недоступный sessionStorage или потеря сети могут оставить события ненаблюдаемыми.
Cookie и постоянного идентификатора человека нет.

visit_id обозначает одну живую вкладку: перезагрузка сохраняет визит; новая
вкладка создаёт новый, BroadcastChannel разделяет вкладки с клонированным
sessionStorage. В браузере без BroadcastChannel клонированные вкладки могут
разделить идентификатор; отчёт считает наблюдаемые визиты, а не уникальных людей.
Каждая отправка поиска, включая повтор, получает search_id; HTTP-запрос получает
request_id. Запрос сохраняется в исходном виде на сервере, текст не дублируется
в продуктовых событиях. Время клиента — диагностическое; client_seq задаёт
локальный порядок, elapsed_ms измеряется монотонными часами до первого видимого
показа результата. Серверный ответ и реальный показ — отдельные факты.

Просмотры отправляются после клиентского commit в видимой вкладке. SSR, ISR,
prefetch и повторный render не создают просмотров. Профиль связывается с выдачей
по явному контексту перехода/позиции; контекст расходуется при показе и истекает
через 30 секунд при незавершённом переходе. Перезагрузка открытого профиля
сохраняет активную привязку; новый прямой переход её не наследует. Модифицированный
клик с открытием новой вкладки считается прямым входом, так как у неё новый визит.
События копирования отражают исход Clipboard API/проверенного fallback,
не клик и не отправку письма. Полный черновик, email и текст посимвольного ввода
в события не включаются.

`NEXT_PUBLIC_SFR_RELEASE` передаётся при сборке (по умолчанию `unknown`).
`SFR_TRUST_PROXY=1` разрешается только в закрытой цепочке Caddy → Next → API,
где внешний клиент не может обратиться прямо к Next. Пересылаются UUID,
ограниченные User-Agent/Accept-Language и URL без query/fragment; произвольные
заголовки, cookie и секреты не пересылаются. Backend дополнительно проверяет
доверенный адрес непосредственного прокси. Эксплуатация и закрытые выгрузки —
[deploy/README.md](../../deploy/README.md).

`SFR_WEB_URL=http://127.0.0.1:18080 make web-e2e` проверяет изолированный стенд,
не запускает второй dev-сервер. `e2e/analytics.spec.ts` использует синтетические
ответы подбора/приёмника для проверки интерфейса и доставки; эти проверки не
доказывают качество FRIDA или сохранность PostgreSQL.
`SFR_ANALYTICS_LIVE_RECEIVER=1` переключает эти тесты на реальный приёмник через
Caddy/Next/API: проверяет явное подтверждение всех IDs, оставляя подбор
синтетическим для воспроизводимости UI. Сохранность записей после перезапусков
и восстановление PostgreSQL проверяются отдельной серверной репетицией.
