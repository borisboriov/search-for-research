**Контекст:** MVP-цикл работает (SFR-0…SFR-3), SFR-4 — фиксы/деплой. Корпус сейчас — 535 профилей МФТИ+МГУ, отобранных как «топ по числу публикаций», из-за чего CS/экономика/гуманитарные направления почти не представлены (запрос «computer science backend engineering» → физики и химики). Эта итерация расширяет каталог по составу вузов и по глубине внутри вуза, чинит долг дедупликации и честно перемеряет качество.
**Прочитай перед стартом:** `docs/NEXT.md`, `docs/SFR4_REPORT.md` (если SFR-4 уже прошёл; иначе — `docs/SFR3_REPORT.md`), `docs/REPORT.md` (проблемы данных SFR-0), `docs/SFR2_REPORT.md` (порог и OOD), `packages/sfr-match/eval/README.md`, `TODO_BORIS.md`, последняя запись `docs/SESSIONS.md`.
**Режим:** автономный. Решения — в `docs/DECISIONS.md`. Только OpenAlex (CC0); **никакого парсинга eLibrary и сайтов вузов в основном каталоге** — юр. решение проекта.

## 1. Скоуп

Делаем: ингест 10 новых вузов; отбор авторов глубже «верхушки»; дедупликация/склейка расщеплённых профилей; пересборка индекса FRIDA; регрессионный eval + перекалибровка обоих порогов; обновление `cards.jsonl`; эксперимент «источник контактов» на 50 профилях (только измерение, в продукт не встраивать); отчёт с честной таблицей «было/стало».
НЕ делаем: фронт/API-логику (кроме того, что нужно для нового индекса и порогов через settings), новые фичи, mpnet-индекс (только если останется время — как запасной), eLibrary.

## 2. Состав каталога

Вузы (resolve через OpenAlex, ID не хардкодить; для каждого — подтвердить в отчёте, что найден правильный institution, а не одноимённый): уже есть МФТИ, МГУ → добавить **ВШЭ, СПбГУ, ИТМО, МГТУ им. Баумана, МИФИ, НИТУ МИСИС, Университет Иннополис, МАИ, НГУ, УрФУ**. Если у вуза несколько OpenAlex-сущностей (филиалы, старые названия) — включить основную и зафиксировать решение.

Отбор авторов — **не только `works_count desc`**: цель — репрезентативность по областям. Правило: для каждого вуза брать авторов по эвристике НР (≥10 работ, публикация за последние 3 года, h-index ≥ 5; пороги в settings) **без верхнего лимита по works_count**, но с квотой на вуз (ориентир 300–800 профилей; для ВШЭ/СПбГУ/МГУ верхняя граница, для Иннополиса — сколько есть). Внутри квоты — стратификация по темам OpenAlex (topics/fields), чтобы CS, экономика, науки о жизни, гуманитарные были представлены пропорционально, а не вытеснены физикой мегаколлабораций. Опиши алгоритм отбора в DECISIONS и покажи в отчёте распределение профилей по вузам и по областям (было/стало).

Целевой размер корпуса: **5 000–8 000 профилей** (лестница из спеки MVP: пилот ≥3 000, полный MVP ≥5 000). Время: OpenAlex ~5 мин на 300 авторов (кэш raw-ответов на месте), эмбеддинг FRIDA на CPU ~10–15 мин на 500 профилей — заложи 2–3 часа на индексацию, запускай фоном, не блокируй остальную работу.

## 3. Дедупликация авторов (долг SFR-0)

Известные случаи: «В. В. Иванов» ×3, «T. Aushev» 984 и 85 работ, NLP-профиль со «Т-клетками мышей» (склейка на стороне OpenAlex), химик Кузнецов с нейтринным экспериментом DANSS. Две задачи разные:
- **Расщеплённые** (один человек — несколько OpenAlex-профилей): склеивать по ORCID + пересечению работ + одинаковой аффилиации; без сигналов — не склеивать (риск склеить тёзок). Показать в отчёте число склеек и 10 примеров для ручной проверки (`eval/dedup_for_review.md`).
- **Склеенные на стороне OpenAlex** (в одном профиле работы двух людей): автоматически не расклеивать; детектор подозрительных профилей (две несвязанные тематические группы работ, разные аффилиации) → флаг `suspect_merge` в карточке, список в отчёте; на фронте пока не показывать.
Мегаколлаборации (works_count > 1000, сотни соавторов): понижать вес таких работ при сборке `profile_text` (решение SFR-0/SFR-1) — реализовать, если ещё нет.

## 4. Качество: регрессия и перекалибровка

- Прогнать `make eval` на новом корпусе: **Success@5 / Success@1 просядут — это ожидаемо**, зафиксировать честно в таблице «535 → N профилей». Судейство новых пар — по рубрике SFR-1, кэшировать в `judgments.jsonl`; `judgments_for_review_sfr5.md` (20 пар) — на ручную проверку.
- **OOD-набор перепроверить**: с ростом корпуса часть из 17 «посторонних» запросов найдёт реальных специалистов (пищевики, ихтиологи уже нашлись на 535) — процедура подтверждения из SFR-2 (контрольный перефраз) применяется заново; посторонними остаются только подтверждённые.
- **Добавить ≥10 академически звучащих посторонних запросов** (античная филология, теория музыки, backend engineering, педагогика начальной школы и т.п.) — именно они пробивали порог 0.27 при score 0.34; часть из них с новыми вузами перестанет быть посторонней — это тоже результат.
- Перекалибровать оба порога (`none` 0.27 и `weak` 0.36 из SFR-4 — если SFR-4 ещё не прошёл, калибруй `none` и предложи `weak`): таблица как в SFR-2, середина безопасного интервала. Порог принадлежит паре модель×индекс — новая версия индекса = новые пороги в settings + в health.
- Внешние запросы (`external_queries.jsonl`, включая запрос Бориса про backend) — прогнать отдельно и показать, куда они попадают.
