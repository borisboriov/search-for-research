## Точный отказ и вмешательства

Первая физическая попытка — официальный ORCID record: status200, полное тело
45487bytes; сохранены raw/decoded/text/source SHA. Вторая —
`https://kpfu.ru/robots.txt`: status null, complete=false, error=ConnectError,
пустое тело. Это **ошибка соединения, не robots disallow и не HTTP403/429**.
Разрешение robots не получено, поэтому страница сотрудника и PDF КФУ не
запрашивались. Исключение loader не преобразовано в продолжение с одним ORCID.
Именно этот операционный путь остановил основной замер; Sol-исхода нет.

Автоматическая проверка разрешений первоначально отклонила команду run до calls
из-за недостаточно конкретного payload/получателя. После чтения полной прямой
постановки и native destination тот же запуск разрешён: OpenAI Codex по имеющейся
подписке, публичный профиль и профессиональные доказательства из frozen ORCID/КФУ.
Credentials/CustDev/human record в payload не входят. Это отдельное вмешательство
для подтверждения разрешения, не обход, не дополнительный model job и не причина
ConnectError. Остаток перед smoke66%; reset/purchase/account switch не выполнялись.

Offline диагностика подтвердила source/body/receipt SHA. Сначала системный Python
не увидел editable модуль; выбран имеющийся locked interpreter. Неверный путь
вспомогательной установки фронта исправлен существующей целью make web-setup.
Эти dev/check ошибки не меняли runtime или основную попытку. Ручная работа:
детерминированная выборка и freeze, 8 поисковых batches/30 queries, 16 выборов
публичного URL и9ORCID; одна проверка отказа approval, offline диагностика,
setup/checks/отчёт. Изменений source plan после результатов и ручного ремонта
конвейера0. Отдельная телеметрия времени/tokens этой агентской работы неизвестна.
