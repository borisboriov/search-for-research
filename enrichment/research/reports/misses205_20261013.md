# Три пропуска контактов после #202 — #205, 13.10.2026

## Итог

На тех же трёх известных профилях получены **три личных email у двух людей по Sol**:
один у Киселева из конференционной презентации 2022 года, два у Кузнецова из
Math-Net. У Горина личный email **в пределах поиска не найден**. Это результат
изменённого набора источников и уточнения личности, без изменения extractor.
Человеческих оценок новых контактов **0**; доставляемость, нынешняя актуальность
и готовность принимать студентов неизвестны. Вердикт: ограниченная диагностика
завершена; два пропуска покрыты агентскими доказательствами, один остаётся.

[Постановка #205](https://github.com/borisboriov/search-for-research/issues/205),
[PR #206](https://github.com/borisboriov/search-for-research/pull/206),
[агрегаты](misses205_metrics.json). Продолжение #193, отдельный этап после merge
#204 (`978293f61e2b99e9bbf7054058f75114cc3d998d`). Это знакомые трудные случаи,
не holdout, не prevalence и не оценка всего каталога. Остальные два человека
из #202 и новые профили не включены.

извлекает email; результат не утверждает отсутствие других способов связи.

## Протокол и исполнение

До нового поиска сохранены `diagnosis.json`, `stage-freeze.json`, profiles/SHA,
база/пакетные code hashes, рубрика/lock, scope и бюджеты. Ровно три author IDs
взяты из #202, без нового отбора. Прежние source/result paths и SHA сохранены
как read-only before; проверены все **748 файлов** его final-transfer-seal,
расхождений0. Старые STOP, метрики и human record не менялись.

Поиск выполнял технический Sol-агент через `web.search_query`: **16 запросов**,
четыре резервирования до вызовов. Для первой четвёрки локально сохранена сводка
выдачи со ссылкой на фактический conversational tool receipt; это не полный
сырой JSON инструмента. Остальные три фактических tool results сохранены целиком.
Это ограничение поискового архива; source evidence получено отдельно из полных
тел, snippets не использованы как доказательства. CLI самостоятельно не ищет.
Первый Math-Net выбран недостаточно точно; конкретное несоответствие предмета
и публикаций обнаружено семантической проверкой. Корректирующий запрос по работе
«Supersymmetric Proof to Count Bound State Nodes» привёл к презентации2022 с
совпадающими физическими якорями/соавтором/МФТИ/ИФВЭ.

Пакет и экстрактор из влитого #204 не менялись: HTTP с сохранением исходных тел,
HTML extractor/pypdf6.19.0, существующий безопасный Math-Net decoder, непрерывные
literal spans, отдельная нормализация и refs. Генеративное извлечение0.
Полная прежняя [рубрика semantic-v3](../../configs/verifier-v3.md) передана
отдельному native Sol; requested model/effort `gpt-6.1-sol/high`, actual backend
model/effort CLI не раскрывает. Identity-only пакет Горина не считается пустым:
он проверен, хотя входных email items0. GLM/Astra профильных jobs0.

Неизменяемые rounds:

1. `run-v1`: два новых HTTP OJS завершены, целевая страница вернула404 и не вошла
   в corpus; подготовка кеша ошибочно перенесла
   старый robots receipt без его body. FileNotFound остановил pipeline до модели.
2. `run-v2`: подготовка исправлена, все referenced cache bodies проверены по SHA.
   Gorin и первичный Kiselev прошли; PDF Kuznetsov после наблюдённого redirect
   вернул503. Этот отказ сохранён, никаких автоматических повторов.
3. `run-v3`: корректирующий plan исключает неподходящий Math-Net Киселева и PDF503,
   добавляет MEPhI PDF. Ошибка controller seed filter: он учитывал ID directories,
   но не ID.json filenames. Несогласованность prepared/collector остановлена
   существующим fail-closed guard до любых новых HTTP/model calls.
4. `run-v4`: фильтр подготовки исправлен; все cache bodies и наследованные inputs
   проверены до live. Готовый Gorin output переиспользован. Один корректирующий
   Kiselev job и первичный Kuznetsov job завершены; карточки готовы.

Это два дефекта ручной подготовки кеша/seed, **не дефекты extractor** и не повод
менять runtime. Они явно отделены, не выданы за загрузочные ошибки сайтов;
исходные failures сохранены. Исправленный Kiselev пакет создан с новым input/SHA
и отдельным native job после установленного разногласия личности. Неподходящий
source record не включён в его итоговый operative corpus; исходный пакет/вердикт
остаются вrun-v2. Другие люди как новые профили не добавлялись.

Bodies/results между rounds hardlinked, без повторной загрузки или копирования
корпусов. Три старых ORCID и небольшие кешированные receipts/robots bodies
переиспользованы по SHA; их старые timestamps сохранены и не выданы за новые
чтения. Source request reservations #202 не перенесены в новый HTTP ledger.
У Math-Net raw и rendered views различаются, но тело одно: окончательный пакет
содержит **7 distinct source bodies /8 views**, включая3 cached ORCID; реально
получено5 новых полных альтернативных тел за этап, одно из них (одноимённый
Math-Net) сохраняется только как ошибка первой проверки.

`audit205.py` отдельно проверил **385 model-visible диапазонов**, source/body/text/
record SHA, exact excerpts, metadata, фактические native prompt/input/raw/events/
receipt SHA и date gates. Все проверки прошли. pypdf предупредил об отсутствии
fontTools для CFF математических шрифтов презентации; зависимости не добавлялись.
Буквальные email/имена/дата проверены по извлечённому тексту и сохранённому PDF;
полное восстановление математических формул не является результатом этого опыта.
