## Реализация, отказы и provenance

Код сохраняет исходный непрерывный email span и отдельно нормализованный адрес
(только пробелы вокруг `@`). Binder заново выводит нормализацию из sealed span,
а точная межисточниковая дедупликация сохраняет все evidence refs. Автоматический
Math-Net renderer использует прежний ограниченный decoder и проверку действительно
наблюдённого URL; произвольный JS не выполняется. Trafilatura/FYP не добавлены.
Извлечение генеративной моделью — 0.

`run --author-id` позволяет smoke на неизменной общей выборке, затем оставшуюся
часть. Незавершённый smoke не выдаёт `completed-progress`; сохранённые outputs
переиспользуются с SHA/source/date проверками. После измерения отдельный export
fix повторно проверяет date gate **всех** результатов, даже при выборе одного
профиля: прежний отказ другого профиля не может попасть в карточки через selector.
Этот fix не меняет извлечение, тела или сохранённые ответы.

Неизменяемые rounds и отказы:

1. `run-v1`, code `5d35fd4`: два источника первого профиля сохранены; native CLI
   умер SIGXFSZ. Ошибочный процессный RLIMIT ограничил также собственные файлы
   клиента. Нет результата/usage; попытка посчитана, расход неизвестен.
2. `run-v2`, `39789f3`: исправление ограничивает только task stdout/stderr
   (16 MiB каждый), timeout включает stdin. Один smoke прошёл; полный запуск
   остановился на robots refusal ВШЭ.
3. `run-v3`, тот же код, план без запрещённого PDF: сохранён ответ Горина;
   date guard отклонил два идентичных ORCID timestamps одного employment объекта.
4. `run-v4`, `863a0ea`: typed guard сохраняет оба JSON-пути при **точно одном
   epoch instant**. Разные instant/объект/неверный unit/будущая дата запрещены.
   Ответ Горина проверен без нового model job; затем два профиля завершены,
   запуск остановлен на robots timeout МАИ.
5. `run-v5`, тот же код, план без HTML МАИ: пятый профиль по уже полученному ORCID
   завершён. Это конкретные исправления и исключения, не новый отбор/авторетрай.

Источники/результаты между rounds hardlinked; parent pointers и оригинальные SHA
не менялись. `paired-audit.json` проверил **404** model-visible excerpt ranges,
body/text/record SHA, metadata, реальный prompt/input и native raw provenance.
Union совпадает с input; refs нового извлечения совпадают с refs collector.
Код измерения сохранён малым `measurement-code`, прежний — `old-code`, без
дублирования корпусов. Повтор offline audit в отдельный output directory дал
тот же набор и проверки, без HTTP/моделей.

Автоматическая проверка разрешений отклонила предложенное смягчение STOP403/429
до recoverable source failure. Оно не применялось: 403/429, challenge, robots,
access/budget/deadline остаются фатальными. Recoverable только 404/410 и
неподдерживаемые форматы/encoding. Разрешение обхода не запрашивалось.
